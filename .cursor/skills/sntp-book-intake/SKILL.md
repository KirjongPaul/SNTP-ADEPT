# Ввод сборника

Для СБЦ и СБЦП сначала читать skill `sntp-sbc-intake`: там паспорт, таблица `a`/`b` и отличие от карточки АСУТП. Реквизиты приказа в Кодексе — skill `sntp-codex-search`. Ниже общий порядок, он же для НЗ.

Каталог лежит вне git: `D:\NET\=SNTP-BOOKS` (`Adept:BooksRoot`). В репозитории только код, схема и этот skill. Таблицы цен в git не коммитить. В MySQL Адепт не писать. «Порядок» Газпрома 2017 не воспроизводить. Существующие таблицы SQL не пересоздавать.

## Папка

```text
НЗ 849-пр 2023 Газовая промышленность\
  book.json
  report.md
  source\   копия для расчёта: текст или codex.html, sources.json (файл, nd Кодекса, сверка с ФРСН)
  letters\  письма-разъяснения, если найдены
  work\     draft.json, check.json, diff.json, decisions.json
```

`book.json` — источник истины (`adept-book.v1`). Параметры `a` и `b` хранятся в тысячах рублей, как в приказе. В смете те же числа лежат в рублях: сравнение и запись в строку умножают на 1000.

Копия в `source/` нужна только обработке: по ней идут два прохода. Пользователь её не открывает. В паспорте поле `codex.nd` — номер документа в интранете. Справочник показывает «Оригинал в Кодексе» и ведёт на `http://techexpert/docs/d?nd=`. Адрес доступен всем в сети организации, личного входа Кодекс не спрашивает.

## Два прохода

1. Первый проход пишет `work/draft.json` по тексту приказа. Для приказа в разметке Markdown подходит `NzMarkdown.Parse`. Числа не брать из Excel: смета — то, что потом сверяем.
2. Второй проход читает только файл источника, не черновик и не `NzMarkdown.cs`, и пишет `work/check.json` со `status: "check"`.
3. `BookDiff.Compare` сравнивает только таблицы, которые есть в check. Расхождение закрывается записью в `decisions.json`: поле, решение, страница источника. Нерешённое остаётся `disputed` в отчёте.
4. Итог копируется в `book.json`. `POST /api/books/sync` пересобирает `AdeptBooks`, `AdeptBookItems`, `AdeptBookNotes`.

## Ловушки пилота 849/пр

- Продолжение строки таблицы наследует номер и название пункта. Строка без «а» и «в» — заголовок группы, не расценка.
- Одиночное число в графе границ — точка, xmin и xmax равны. Так устроены полосы таблиц 3.3 и 3.4. Если оставить границы пустыми, второй проход разойдётся с первым, хотя «а» и «в» те же.
- Граница «до 10 включительно» и следующая «от 10» стыкуются. Значение ровно на границе относится к нижней полосе, иначе подбор видит группу.
- Примечания под таблицей нумеруются с 1 и кончаются перед следующим пунктом главы (номер больше 20) или перед словом «Таблица».
- Якорь справки: `item:3.8/10`, иначе `table:3.8`, `general:13`, `rule:interpolate-below-min`. Фрагмент без якоря в справку не попадает.
- Отдельного письма Минстроя по 849/пр в открытом доступе не нашлось. Справка пилота — примечания самого приказа. Поиск пишется в `sources.json` и `report.md`.
- Пункт 13 отсылает интерполяцию и экстраполяцию к формулам (8.1)–(8.8) Методики 707/пр. В движке это уже есть: внутри диапазона `(A+B·X)·K`, ниже минимума `(A+B·(0,4·Xmin+0,6·X))·K`, выше максимума с `Xmax`, ниже `0,5·Xmin` добавляется Кпон.

## Правила

Текст приказа не компилируется. Требование относится к одному из видов: `range-select`, `interpolate-below-min`, `extrapolate-above-max`, `kpon-below-half`, `share-of-position`, `factor-when`. У правила в JSON пункт и страница. Неузнанное требование — строка «нужен новый вид правила» в отчёте, в расчёт не идёт.

## Усложняющие факторы

Общая переменная объявляется в `FactorCatalog`, если текст коэффициента общей таблицы (не `3.1.1`) содержит известный признак: историческая среда, сероводород, стеснённые условия, теплоизоляция. Системное имя латинское (`hydrogenSulfide`), для человека — русское (`Сероводород`). У переменной список сборников: в каждом своё значение и свои таблицы цены. Коэффициент одной таблицы цены переменной не становится.

На проекте переменная включается один раз. В расчёт строки она попадает, если основание строки или её объём относится к этому сборнику и к одной из таблиц цены.

## Просмотр

`report.md` читается вместе со сборником, но рисуется отдельным блоком «Сверка» под текстом. Это факт двух проходов, не пункт СБЦ и не примечание приказа.

Поиск по открытому сборнику стоит в полосе разделов каталога, справа от «Сборники». Полоса липкая. «Вверх» и «Вниз», Enter и Shift+Enter ходят по подсветке. К перечню сборников возвращает повторное нажатие «Сборники».

Расценка перетаскивается на номер локальной сметы. В `dragstart` пишутся `text/plain` и `application/x-sntp-volume`. Пока курсор над номером, читается только список типов: в Chrome `getData` до события `drop` пустой. Тот же номер уже принимает перенос соседней сметы через `text/plain` с её id. Расценку отличает свой тип, иначе отпуск на номере сдвинет оглавление.
