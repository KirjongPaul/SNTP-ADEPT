# Поиск в Кодексе

Сервер: `http://techexpert/docs/`. Оболочка — ИС «Кодекс: 6 поколение» Интранет v. 6.4.5.127. Отдельной плитки «Стройэксперт» на этой главной нет. Строительные продукты здесь: «Техэксперт: Помощник проектировщика» (`777717034`), «Стройтехнолог» (`777714425`), «Техэксперт Реестр требований: Строительство» (`450000985`). Остальные плитки тоже Техэксперт и уже включены.

Для расчёта нужна своя копия: текст или HTML карточки (`.text.longDoc`) кладётся в `source/` сборника, вне git. Пользователю эта копия не показывается. Ему в справочнике даётся прямая ссылка Кодекс `http://techexpert/docs/d?nd={nd}` — её сервер сам собирает из `book.json` → `codex.nd`. В git не класть ни копию, ни таблицы цен, ни PDF/RTF.

## Куда смотреть

Интерфейс не в верхнем документе, а в единственном iframe (`location` содержит `frame=left`). Снимок страницы этот iframe не видит. Команды выполнять в `contentWindow` этого iframe через jQuery страницы (`win.jQuery`) и `win.kApp`. Имя iframe каждый раз новое, на `id` не опираться.

Пока идёт сверка, вкладку не уводить на другой сайт. «Печать», «Сохранить в файл» и выгрузку списка в xlsx не нажимать.

## Интеллектуальный поиск

На главной строка — `input#context2` (плейсхолдер «введите фразу для поиска», maxlength 400). Кнопка — `.iSearchForm-findBtn`. Очистка — `#onMainPage`.

В шапке открытого документа строка уже `#context`, кнопка `.iSearchForm-contextButton`, очистка `#inHeader`. Обе кнопки вызывают `kApp.iSearch.searchByNames`.

```javascript
const frame = [...document.querySelectorAll('iframe')]
  .find(f => f.contentWindow.location.href.includes('frame=left'));
const win = frame.contentWindow;
const $ = win.jQuery;
const input = $('#context2').length ? $('#context2') : $('#context');
input.val('849/пр');
$('.iSearchForm-findBtn, .iSearchForm-contextButton').first().trigger('click');
```

Пустую строку кнопка не отправляет. Запрос система сама режет на атрибуты: вид документа, номер, слова. Номер приказа писать как в реквизите (`849/пр`), не слитно.

Список: `li.docItem[data-nd]`. Название — `.annotationcontent span.title`. Строка под ним — вид, орган, дата и номер. Значок `.documentIconNew` несёт статус в `title` («Действующий документ»).

Открыть карточку: `win.kApp.iSearch.select(li, { type: 'click', shiftKey: false, ctrlKey: false })`. Shift открывает новое окно, его не ставить. Постоянный адрес, который Кодекс копирует как прямую ссылку, — `http://techexpert/docs/d?nd={data-nd}`. Его и писать в `codex.nd` (только цифры). Протокол `kodeks://link/d?nd=` нужен кАссист и в справочник не кладётся.

## Карточка

Корень текста: `.document.activeDoc .text.longDoc`, id `longDoc_{nd}`.

- Статус: `#ico_statusPopup`. Панель `.statusPopup-content`. Состояние — `.statusPopup-acting` («Действующий»), дата — `.statusPopup-actingDate`. Здесь же орган, номер и вид. Для паспорта сборника брать эти поля, не абзацы приказа.
- Оглавление: `#ico_table_content`. Пункты — `.sidePanel .treeTOC-node`. Свёрнутый пункт имеет `treeTOC-folded`.
- Поиск по тексту открытого документа: `#ico_find`, поле `#textSearch-value`.
- Назад по истории: `#prev`. На главную: `.navigation-home`.

## Атрибутный поиск

С главной: `.aSearch` («Атрибутный поиск»). Вкладки — `.asearch-tab-text`. Для СП, ГОСТ и сборников цен открывать «Нормы, правила, стандарты». Поля:

| id | поле |
| --- | --- |
| `asearch_input_0` | Наименование |
| `asearch_input_1` | Вид документа |
| `asearch_input_2` | Принявший орган |
| `asearch_input_3` | Номер |
| `asearch_input_6` | Действие |
| `asearch_input_27` | По тексту |

Номер и орган для сверки `OrderRef` надёжнее искать здесь, чем общей фразой. Классификатор выбирается щелчком по полю, свободный текст туда не вбивать.

Если вёрстка не совпала с этим skill, селектор перечитать в iframe. Версия на этой сверке — 6.4.5.127.
