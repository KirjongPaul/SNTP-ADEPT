# /I - Internet Research (Исследование и анализ)

## Использование
```
/I [описание проблемы или технического вопроса]
```

**Примеры:**
- `/I Как лучше реализовать кэширование в VB.NET WebAPI`
- `/I SignalR отключается при длительных операциях`
- `/I Оптимизация SQL запросов с большим количеством JOIN`

---

## Алгоритм исследования

При получении `/I [вопрос]` выполнить **полный цикл исследования**:

```
Поиск → Анализ → Сравнение → Решение → Риски
```

---

### Фаза 1: Сбор информации

**1.1. Формулировка поисковых запросов**

Сформировать 3-5 поисковых запросов разной направленности:
- Общий запрос по проблеме
- Запрос с указанием технологии/языка (VB.NET, JavaScript, SQL Server)
- Запрос "best practices" / "рекомендации"
- Запрос "common issues" / "типичные ошибки"
- Запрос с альтернативными решениями

**1.2. Выполнение поиска**

```
WebSearch: [поисковый запрос 1]
WebSearch: [поисковый запрос 2]
WebSearch: [поисковый запрос 3]
...
```

**1.3. Углублённое изучение (при необходимости)**

```
WebFetch: [URL из результатов поиска] - для детального изучения статьи/документации
```

---

### Фаза 2: Систематизация найденной информации

**Структура анализа:**

```markdown
## Найденная информация

### Источник 1: [название/URL]
- **Суть:** краткое описание
- **Применимость:** насколько релевантно для нашего случая
- **Ключевые моменты:** список важных пунктов

### Источник 2: [название/URL]
...
```

**Критерии оценки источников:**
| Критерий | Вес |
|----------|-----|
| Актуальность (дата публикации) | Высокий |
| Авторитетность (официальная документация, известные эксперты) | Высокий |
| Применимость к нашему стеку (VB.NET, SQL Server, JavaScript) | Критичный |
| Наличие примеров кода | Средний |
| Отзывы сообщества | Средний |

```markdown

### Преимущества

- ✅ Преимущество 2

- ❌ Недостаток 1
- ❌ Недостаток 2

### Требуемые изменения
- Файлы: [список файлов]
- Зависимости: [новые пакеты/библиотеки]
- БД: [изменения схемы если нужно]

### Пример реализации
[Код или псевдокод]
```

### Фаза 5: Принятие решения

**Формат рекомендации:**

```markdown

### Выбор: Вариант [X]

### Обоснование
1. [Главная причина выбора]
2. [Вторая причина]
3. [Третья причина]

### Почему НЕ другие варианты
- Вариант A: [причина отклонения]
- Вариант B: [причина отклонения]

### Уровень уверенности
[Высокий / Средний / Низкий] - [обоснование]
```

|------|-------------------|-----------------|
| Риск 1 | Что сделать заранее | Что делать если случится |

---

## Важные принципы

1. **Объективность:** Не предвзятая оценка всех вариантов
2. **Применимость:** Фокус на нашем технологическом стеке (VB.NET, SQL Server, JavaScript)
3. **Практичность:** Реальные примеры и код, а не абстрактные рекомендации
4. **Честность:** Открыто указывать на риски и неопределённости
5. **Актуальность:** Приоритет свежим источникам (2024-2026)
