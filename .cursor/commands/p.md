# /p - План изменений

## Использование
```
/p <описание задачи>
```

---

## Описание

Команда для генерации детального плана изменений перед написанием кода. План должен содержать **ссылки на документацию для изучения перед кодированием, ссылки на лучшие практики для изучения перед кодированием, анализ решений Internet, ключевые структуры данных** для качественной пошаговой генерации кода Cursor AI. **Придумай, улучши, оптимизируй прими или опровергни**!

---

## ВАЖНО
- **план составляй на руссом языке**
- **Гранулярность правок** — каждое изменение изолировать по классу/функции/блоку; не группировать несвязанный код в один шаг, чтобы Cursor AI не затронул соседние участки при внесении изменений
- **SQL таблицы пересоздавать НЕЛЬЗЯ** — в плане предусмотреть идемпотентный `ALTER` и шаг применения через MCP `SNTP SQL` (`sql_execute_query`) с проверкой результата
- **Выбирай лучший вариант кода** — без компромиссов, оптимальное решение
- **Обратная совместимость НЕ нужна** — можно ломать старый API/структуры
- **Используй Internet для поиска, сраванения решений и уточнения документации**
- **Включай в план текст и отладку MCP**
- **Если предлагаешь варианты выбора пиши какой приорететный и почему**
- **По окончании плана выполняй ревизию** Важно если код не корректен, не оптимален перепиши его как с чистого листа. Исправь ошибки в коде. Доработай код где были заглушки TODO . Написано будет реализовано или чатично реализовано, где код не полный

---

## Принципы составления плана

1. **Максимальная декомпозиция** — разбить задачу на минимальные атомарные шаги
2. **Один шаг = одно действие** — каждый шаг должен быть выполним за одну операцию
3. **Указывать файлы и строки** — конкретные места изменений; один класс/метод = отдельный шаг
4. **Порядок зависимостей** — сначала prerequisite, потом зависимые шаги
5. **Полный цикл** — подготовка → код → документация → тест → деплой
6. **Приводи ссылки на документацию, ссылки на Intrenet**

---

## Критерии качественного плана

- [ ] Каждый шаг атомарный (одно действие)
- [ ] Правки изолированы по классу/методу — нет смешанных шагов с несвязанным кодом
- [ ] Указаны конкретные файлы и строки
- [ ] Есть примеры кода где нужно
- [ ] Включены шаги документации (для JS)
- [ ] Включены шаги тестирования
- [ ] Копировать WWWRoot в Bin\Debug не нужно сервер перет файлы по пути размещения
- [ ] Чем больше шагов — тем лучше для генерации
