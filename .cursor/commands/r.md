# /r - Ревизия плана

## Использование
```
/r <контекст или ссылка на план/файл/функцию>
```

---

## Описание

Команда для глубокой ревизии кода с проверкой полноты, корректности, исправлением ошибок и составлением анализа сильных/слабых сторон. Важно если код не корректен, не оптимален перепиши его как с чистого листа. Обратной совместимости не нужно. Таблицы SQL пересоздавать НЕЛЬЗЯ: структуру менять идемпотентным `ALTER` и применять через MCP `SNTP SQL` (`sql_execute_query`) — см. `.cursor/rules/sql.mdc`.

Если работаешь с In-Memory таблицами изучи опыт D:\Program\Cursor\SNTP-CRM+\SNTP_API_Server\-SQL\ExecutionControl_01_CREATE_STORED_PROCEDURES.SQL

**Важно При обнаружении некачественного кода — переписать с чистого листа.**
**Доработай код где были заглушки TODO . Написано будет реализовано или чатично реализовано, где код не полный**
---

## 🔴 КЛЮЧЕВЫЕ ПРИНЦИПЫ РЕВИЗИИ

### 1. Беспощадная честность
- **НЕ замалчивать** проблемы ради экономии времени
- **НЕ оставлять** костыли с комментариями "потом исправим"
- **НЕ бояться** переписывать большие куски кода
- **Зафиксируй отсупления от плана проанализируй их обоснованность и доработай код**
- **Исправь ошибки в коде, дополни код**

### 2. Качество > Скорость
- Лучше потратить время на правильную реализацию, чем быстро сделать плохо
- Код должен быть понятен через 6 месяцев без комментариев автора

### 3. Принцип чистого листа
- Если функция некачественная → **переписать полностью**
- Не патчить плохой код — заменять хорошим

### 4. ⚠️ ОБРАТНАЯ СОВМЕСТИМОСТЬ НЕ ТРЕБУЕТСЯ
- **НЕ сохранять** старые сигнатуры функций ради совместимости
- **НЕ поддерживать** устаревшие форматы данных
- **НЕ бояться** ломать существующие вызовы — они будут обновлены
- Переписывать API так, как правильно, а не "чтобы не сломать"
- После переписывания → найти и обновить ВСЕ вызовы через Grep
- ВАЖНО **составь что не выполнено, что нужно изменить проанализируй зафиксируй исправь код**
- ВАЖНО **по завершении обязательно выполни аудит изменений кода которые к данной задачи не относились или не требовались -верни исправления обратно!**
- 
### 5. Категоризация найденных проблем

| Категория | Уровень | Действие |
|-----------|---------|----------|
| **Критическая ошибка** | 🔴 | Исправить немедленно |
| **Логическая ошибка** | 🟠 | Исправить с тестированием |
| **Плохой дизайн** | 🟡 | Рефакторинг или переписать |
| **Код-запах** | 🟢 | Улучшить если время есть |
| **Стилистика** | ⚪ | Исправить при касании |
