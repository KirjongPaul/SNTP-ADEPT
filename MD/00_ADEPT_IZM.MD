## 1. Кто мы и идеал импорта

Проект **SNTP-ADEPT**: десктоп (WebView2) читает Excel смет ПИР (пилот «Степновская ПХГ») и XML проектной сметы Гранда, держит канон JSON **PIR-IR**, считает A+B·X (интерполяция/экстраполяция/Кпон), выгружает XML Гранда без `GrandSmetaSign`. В Адепт:Проект открытого формата импорта ПИР нет; CXA/toaus — отдельный этап у вендора.

**Идеал при импорте (главный запрос к поиску):**

При разборе Excel или XML программа должна:

1. **Распознать ссылку на сборник** в обосновании / коде / тексте формулы: СБЦ, СБЦП, СЦ, НЗ, МРР, ведомственный сборник (Газпром, РЖД, Роснефть…), письмо Минстроя / ЦЕНТРИНВЕСТпроект.
2. Разобрать структуру ссылки: **документ + год/приказ + таблица + пункт + интервал (Xmin–Xmax)**.
3. **Сопоставить с базой сборника** (наш справочник кодов, не дамп чужой СНБ): статус `matched` / `partial` / `catalog-miss` / `ambiguous`.
4. **Распознать коэффициенты** (Ктек, Кст, Кпон, Ки1, районный, ведомственный, «учитывать / не учитывать / печатать») и сопоставить со справочником коэффициентов (тип: ценообразующий / усложняющий / составной / делитель).
5. Выдать протокол сопоставления: что взято из файла, что из каталога, что сметчик должен уточнить.
6. **То же на лету из буфера**, без полного файла книги: скопировали 1 строку или прямоугольник ячеек в Excel → вставили в наш бланк → получили позиции PIR-IR (и при необходимости заголовки), а не «простыню текста».

Искать в интернете: как это делают Адепт, Гранд, Смета.ру, Госстройсмета, АВС, РИК, Estimo; есть ли открытые кодификаторы СБЦП/НЗ; как кодируют обоснование в XML; **мастер вставки из Word/Excel** (сопоставление колонок + тип строки).

### 1.1. Вставка на лету (строка / таблица из Excel)

Сценарий продукта (ещё не реализован; искать аналоги):

1. Сметчик в Excel выделяет **одну позицию**, блок позиций, **шапку листа** или таблицу с разделами → Ctrl+C.
2. В нашем WebView2: Ctrl+V на бланке 2П (или кнопка «Вставить из буфера»).
3. Хост читает буфер Windows (не только `text/plain`): приоритет **XML Spreadsheet 2003** / **HTML-таблица** (есть сетка и иногда формулы) → запас TSV.
4. Классификатор каждой строки (см. §1.2): шапка документа / заголовок колонок / раздел / текст / позиция / начисление / итог / мусор.
5. Для позиций — тот же матчер сборников, что при импорте файла. Стоимости из Excel — **контроль**, A/B/Xmin/Xmax — из каталога, если код найден; иначе seed с листа + `catalog-miss`.
6. Превью как у Гранда: сопоставить колонки (№, наименование, обоснование, ед., X, формула, ₽), переключить тип строки тремя значками, отключить шапку/итоги, затем «Вставить» уже **нашими** `Position` / `Chapter` / `ProjectHeader`.
7. Одна строка без сетки (просто «НЗ 849 табл. 3.8 п.10» в буфере) — поиск по каталогу и вставка пустой позиции с кодом, X уточнить.

Ограничения WebView2: Ctrl+T/W/N заняты Chromium — вставку перехватывать **в хосте WPF**. Формулы Excel в HTML-буфере часто только кэш значения; для ROUND нужен XML Spreadsheet или полный файл.

Эталон для изучения (СМР, но UX копировать):  
https://help.grandsmeta.ru/dobavlenie-pozitsij-v-smetu-struktura-smety/19-import-dannykh-iz-word-i-excel/vstavka-pozitsij-smety-iz-word-i-excel/kopiruem-vsyu-smetu-s-razdelami  

Гранд: окно «Параметры вставки» → заголовки разделов распознаются не как позиции; три значка на строку (позиция / заголовок / текстовый комментарий); колонки перетаскиваются; шапку и итоги можно не вставлять; обоснование ищется в СНБ (~8 с на 94 позиции); **стоимости из Excel по умолчанию не брать** — из базы; после вставки текстовые заголовки отдельно «Преобразовать в раздел»; проверка расценок. Для ПИР то же + колонки A, B, Xmin, Xmax, формула `(A+B·X)*Ki`.

Адепт:Проект: Ctrl+C/V общие; **Ctrl+U** раздел, **Ctrl+T** текстовая строка; «Создание строки» (характеристика, обоснование, формула, стоимость) — **не** привязка к СНБ. Отдельного мастера «вставить таблицу Excel в 2П» в справке модуля ПРОЕКТ нет (импорт Excel — СМР). Искать подтверждение/опровержение.

### 1.2. Вставка заголовков — четыре разных объекта (не путать)

| Что в быту зовут «заголовок» | Где живёт | Как вставлять | У нас сейчас |
|---|---|---|---|
| **Шапка документа** (объект, стадия, заказчик, № сметы, договор, НДС) | `ProjectHeader` / печать `/smeta` `@customer` `@Stady` `@SmetHeaderName` | Из первых строк Excel или титула; Гранд: «из печатного документа скопировать титульные данные и подписи» | Парсер файла читает шапку листа 1ПС / 2П; из буфера — нет |
| **Шапка колонок бланка** («№», «Наименование», «Обоснование», «Расчёт», «Стоимость») | только UI/маппинг | Нужна, чтобы понять, какая колонка буфера = какое поле. Не строка сметы | При файле — жёсткие индексы колонок по диалекту; при вставке нужен сдвиг колонок как у Гранда |
| **Заголовок раздела** (`Chapter`, Адепт Ctrl+U) | группирует позиции; в XML Гранда `Chapters/Chapter/@Caption` | Распознать строку без номера и без A/B («Раздел 1. Генеральный план») → `PositionKind.Section` или новый chapter. Не считать ₽ | `IsSectionHeader` при импорте файла (эвристика); в XML пишем **один** `ChapterCaption`; `PositionKind.Section` в enum есть, строками почти не создаём |
| **Текстовая строка / комментарий** (Адепт Ctrl+T; Гранд «текстовый комментарий») | печать, не расчёт | «Примечание», обрыв фразы, ТЧ сборника без кода | Нет отдельного kind; часть уходит в `groupText` к предыдущей позиции |

Печать Адепт: `smeta/row/@rascHeader` `@subRasc` `@font` `@colspan` — заголовок расценки vs подрубрика. Искать полный словарь атрибутов.

Гранд специально **не** делает из распознанного заголовка сразу раздел: в целевой смете уже может быть своя нарезка; перевод «текст → раздел» — вторая команда. Нам: в превью предлагать тип, по умолчанию «раздел» если строка похожа на «Раздел N …» / длинное имя без цифры в колонке №.

Свод 1ПС: строки 1.1–1.14 — **не** заголовки разделов локальной, а ссылки на локальные сметы. Не вставлять их как позиции 2П.

### 2.3. Гранд: что выгружается в XML (проверено 2026-08-15)

- Справка: https://help.grandsmeta.ru/ob-ekty-i-smety/eksport-smet-v-razlichnye-formaty/eksport-v-format-xml

- Публичные XSD: https://xsd.grandsmeta.ru/ — локальная смета, ОС/ССР, смета контракта, КА, ВОР, ценник, **пользовательский сборник**. **XSD проектной сметы ПИР нет.**  
- Скачано: `OpenXML_LS_2026.1.1.xsd` — единственный GUID `{2B0470FD-…}` «Локальная смета».  
- `OpenXML-UserNBDoc 2026.1.3.xsd` — пользовательский сборник СМР (ТЕР/ФЕР/ТС, ресурсы, ПНР), не таблицы A+B·X СБЦП.  
- Официальная СНБ ПИР Гранда — платный регион «Проектно-изыскательские работы»; штатного «выгрузить весь СБЦП в XML» нет.  
- Образец `MD/Проектная смета.xml`: в `Items` — интервалы **использованной** расценки (A/B/Xmin/Xmax), не весь сборник. Это легальный seed для матчера, не дамп СНБ.

## 5. Критерий полезного ответа поиска

Считать поиск успешным, если появились:

1. Любой **документированный** канал импорта сметы ПИР в Адепт:Проект (не СМР) — файл, API, партнёрский конвертер — с URL.
2. Публичный **кодификатор** СБЦП/НЗ (хотя бы правила кода: сборник-таблица-пункт) или открытый фрагмент ФРСН.
3. Актуальные **письма индексов ПИР** и ведомственных К (Газпром, РЖД), которых нет в нашем `.apr`.
4. Подтверждение или опровержение: Адепт 2026 **не** читает GUID `{39200715-…}`.
5. Описание `.toaus` / ограничения версии 2025.1.
6. Список форм печати / методик Адепт:Проект, которых нет в нашем пилоте (изыскания 3П, 4П, МРР, НМЦ, ГГЭ ПИР).
7. Работает ли мастер вставки Гранда **на проектной смете ПИР**; скрины/список колонок 2П в «Параметрах вставки».
8. Словарь типов строк Адепт (раздел / текст / расценка / работа / свободная) и атрибуты печати `rascHeader`.

Если канала в Адепт нет — явно написать «не найдено» и предложить формулировку письма в ГК Адепт (интеграция Excel/XML ПИР → CXA/toaus + справочник кодов).

## 6. Как встроить находки в продукт (памятка себе)

После ответа Perplexity:

- Новые **открытые** кодировки сборников → словарь матчера (обоснование Excel / `Code` Гранда / код Адепт) в `dbo.AdeptCatalogRates`, статусы `matched|partial|catalog-miss|ambiguous`.
- Новые коэффициенты → снимок рядом с `.apr`, не вместо него; сверка Ктек пилота 1.56 с письмом Минстроя.
- Если появится спецификация CXA/toaus от вендора — отдельный этап экспорта; до тех пор выход = PIR-IR + XML Гранда `{39200715-…}`.
- Находки по СМР-импорту Адепта не меняют контур ПИР, только помечаются «модуль Смета, не Проект».
- UX вставки Гранда (колонки + тип строки + не брать ₽ из Excel) переносить в наш Ctrl+V; матчер СНБ — общий с импортом файла.
- Заголовки: шапка объекта → `ProjectHeader`; колонки → карта вставки; раздел → `Chapter` / `PositionKind.Section`; текст → отдельный kind, в XML Гранда не как `Position` с A/B.
- WebView2: paste в хосте; читать HTML и XML Spreadsheet, не только TSV.

Не переносить в продукт: выгрузку коммерческой СНБ Адепт/Гранд, робот UIA по `adept_us`, запись в MySQL Адепт.
