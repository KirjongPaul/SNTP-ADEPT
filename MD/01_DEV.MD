## 2. Что ещё нужно исследовать (Гранд / Адепт)

Не блокирует P0–P5, но нужно до полноценного обмена:

**Гранд**

- Смета изысканий; формы 3П/4П; заполненные `Indexes` и `AddZatrats`.
- `Crypted=True` — не читать без ключа.
- Как Гранд 16 открывает наш unsigned XML (ручная проверка на машине с Грандом).
- Свода ПИР как типа документа в курсе нет — пакет N XML + наш 1ПС.

**Адепт**

- Эталон `.cxa` / `.toaus` штатным «Сохранить в файл» (не разбирать бинарник).
- Снимок справочника коэффициентов (только чтение имён/типов) — E7.
- Письмо вендору: импорт ПИР / CXA.
- Не писать в MySQL, не реверсить `.cxa` / `.apr`.

### 3.2. 2П 707/пр (листы 1.1–1.4)

Детектор: R1C5 содержит `форма 2П, 707/пр`.

Колонки (после merge): **A** №, **B** наименование, **G** обоснование НЗ, **K** расчёт (текст), **O** стоимость.

| Лист | Смета | Итог O (Всего) |
|---|---|---|
| РД 1.1 ГП | №1.1 | 432275.9308 → свод 432275.93 |
| 1.2 Автодороги | №1.2 | 328108.788 |
| 1.3 ТХ | №1.3 | 7074839.548 |
| 1.4 ОВ | №1.4 | 2241396.2277 |

Позиция: блок «№ + обоснование с A/B/Xзад» + следующие строки «Кст=», «Ктек=», опционально «К'пон=».

Regex обоснования: `A = … тыс.руб`, `B = …`, `Xзад`/`Хзад`/`L =`, `Xмин`/`Xмакс`, `Количество`. A/B в тыс. → ×1000 в PIR-IR (рубли).

Начисления сметы (не позиции 707): «Новое начисление» К=0.8 Газпром, К=1.08 районный; «Всего» × `Kобъем=0,28`.

Примеры экстраполяции (1.3): X>Xmax п.6; X<0.5 Xmin + Кпон п.7 и п.11.

### 3.3. Карточка АСУТП (1.5–1.8)

Детектор: имя листа / «СБЦ … АСУТП».

Шаблон ~176 строк: факторы Ф1–Фn, баллы, К1…Кст(П/Р), расчёт базовой цены по частям ТЗ/ОР/ОО/ИО/ТО/МО/ПО.

Итог 1.5: **R174 C4 = 1565712** («Итого цена стадии Р»). То же в C25.

Парсер MVP: шапка (№ сметы, стадия, организация), итоговая сумма, коэффициенты К1/Кст/Кин если видны. Остальное → `issues` (уточнение «карточка АСУТП»).

### 3.4. Классическая 2П СБЦ (1.9–1.12)

Детектор: R1C5 `Форма 2П` без `707`.

Колонки A–E: №, характеристика, обоснование СБЦ, формула `(a+bx)*Ki` текстом, стоимость.

Строки коэффициентов: C = `К=0,6(стадия Р)` и т.п.

1.11: плюс К оптимизации 0.8, районный 1.08, Kобъем 0.28 (как 707).

Формулы разношёрстные: `2304x0,6x54,34x…`, `(1020+15x15)x0,52x7,1`.

## 5. Как запускать

```
dotnet test Sntp.Adept.sln
dotnet build Sntp.Adept.sln
cd web && npm install && npm run build
dotnet run --project src/Sntp.Adept.Host
```

Хост поднимает Kestrel на `127.0.0.1:5179` (или свободный порт) и открывает SPA в WebView2. Данные: SQL Server `SNTP_PPO`, таблица `dbo.AdeptProjects` (PIR-IR JSON).

### База `SNTP_PPO` (как в SNTP-Крипто)

Паттерн скопирован с `D:\Program\Cursor\SNTP-Крипто`: SQL Server, ADO.NET (`Microsoft.Data.SqlClient`) + Dapper, Windows Integrated, имя строки `ConnectionStrings:SNTP_PPO`. User Secrets нет — строка в `appsettings.json`, переопределение через переменную окружения `ConnectionStrings__SNTP_PPO`.

Файл: `src/Sntp.Adept.Api/appsettings.json`

```json
"ConnectionStrings": {
  "SNTP_PPO": "Server=SQL16-APP;Database=SNTP_PPO;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=True;"
}
```

При старте API/Host вызывает `ProjectStore.InitializeAsync()` и создаёт таблицы, если у логина есть `CREATE TABLE`. Если прав нет — DBA один раз выполняет скрипт (чужие таблицы не трогает):

```
sqlcmd -S SQL16-APP -d SNTP_PPO -E -i Database/AdeptTables.sql
```

| Объект | Назначение |
|---|---|
| `dbo.AdeptProjects` | Объект ПИР: `Id`, `Name`, `PirJson` (весь PIR-IR, включая сметы и свод), `UpdatedAt` |

Префикс `Adept*` / схема `dbo` — как `Crypto*` у Крипто, без столкновения с `CryptoSigningJobs` и справочниками. Локальный SQLite `%LocalAppData%\SntpAdept\adept.db` больше не используется.

**С нуля (без Excel):** шапка → «Новый объект» → «Новая локальная смета» → «+ Позиция» (A/B/X в инспекторе) → «Создать свод 1ПС» → вкладка «Экспорт».

**Из Excel/XML:** вкладка «Импорт» → файл → тот же редактор и экспорт.

### Создать vs импорт (обязательный контур)
Импорт Excel **не** единственный путь. Объект и локальные 2П создаются пустыми и живут в том же PIR-IR / сетке / инспекторе / пересчёте / XML.

| Действие | API | UI |
|---|---|---|
| Новый объект | `POST /api/projects` | «Новый объект»: имя, стадия П/РД/РП, заказчик, проектировщик, НДС, Ктек |
| Новая локальная 2П | `POST /api/projects/{id}/estimates` | «Новая локальная смета»: пустая 2П, Ки1 0,4/0,6/1, раздел «Новый раздел» |
| Позиция | `POST /api/projects/{id}/estimates/{estId}/positions` | «+ Позиция» |
| Свод 1ПС | `POST /api/projects/{id}/summary` | «Создать свод 1ПС» — строки из локальных, НДС |
| Импорт Excel | `POST /api/import/excel` | вкладка «Импорт» — заполняет уже существующую модель объекта |
| Импорт Гранд | `POST /api/import/grand-xml` | XML/GSFX → тот же объект |

`DocumentFactory` (`src/Sntp.Adept.Domain/Documents/DocumentFactory.cs`): `CreateObject`, `CreateLocal`, `CreatePosition`, `RebuildSummary`.
