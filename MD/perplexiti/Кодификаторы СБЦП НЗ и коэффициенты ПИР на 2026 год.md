## 1. Как кодируется обоснование расценки ПИР в разных системах

### 1.1. Базовый шифр государственного сметного норматива СБЦП

Официально у каждого СБЦП **два равнозначных шифра**, и это главная причина расхождений при сопоставлении. По разъяснению в базе NormaCS, для «Железных дорог» действуют оба обозначения — `СБЦП 81-02-09-2001` и `СБЦП 81-2001-09`, «в ссылках Вы можете указывать любой номер (оба номера правильные, СБЦП 81-2001-09 — более короткий вариант)» ([NormaCS, ответ № 1206, 23.04.2015](https://www.normacs.info/answers/1206)).

Расшифровка групп (там же):

| Группа | Значение |
|---|---|
| `81` | сметные нормативы в строительстве |
| `02` | проектные работы (тип сборника) |
| `09` | порядковый номер ГСН на проектные работы |
| `2001` | базовый уровень цен |

То есть `СБЦП 81-02-**NN**-2001` ≡ `СБЦП 81-2001-**NN**`. Нумерация введена Минрегионом с 2010 года ([NormaCS](https://www.normacs.info/answers/1206)). Реальный документ подтверждает двойное обозначение в самом заголовке: «СБЦП 81-2001-17. СБЦП 81-02-17-2001. Государственный сметный норматив. Справочник базовых цен на проектные работы в строительстве. Объекты водоснабжения и канализации» ([Меганорм](https://meganorm.ru/mega_doc/norm/normativy/0/sbtsp_81-2001-17_sbtsp_81-02-17-2001_gosudarstvennyy_smetnyy.html)).

Аналогичная логика четырёхгруппового шифра для ФЕР/ТЕР — `81-02-01-2001`: `81` — шифр сметных нормативов, `02` — шифр сборников по типу работ, `01` — порядковый номер сборника, `2001` — год выпуска базы ([General-Smeta, вики «Шифр»](https://general-smeta.ru/wiki/wiki-sh/2450-shifr.html)).

### 1.2. Структура «адрес внутри справочника»: раздел → таблица → пункт → интервал

Внутренняя адресация расценки ПИР в справочнике — иерархия «часть / глава / таблица / пункт (позиция) / диапазон значений основного показателя». Именно эти четыре поля отображает ПК «ГРАНД-Смета» в дополнительной информации о расценке проектного сборника: в разделе **Прочее** — «номер части, номер главы, номер таблицы соответствующей позиции исходного справочника базовых цен на проектные работы», а в разделе **Диапазон значений** — «соответствующий диапазон значений основного показателя проектируемого объекта» для каждой единичной расценки в группе ([Онлайн-справка ГРАНД-Смета, «Сборник на проектные работы»](https://help.grandsmeta.ru/dopolnitelnye-rezhimy/26-smety-na-proektno-izyskatelskie-raboty/normativnaya-baza-na-proektno-izyskatelskie-raboty/sbornik-na-proektnye-raboty)).

Практическое следствие для парсера: **позиция + интервал** — это не два независимых атрибута, а «пункт таблицы» и «поддиапазон внутри пункта», по которому программа автоматически перевыбирает расценку при изменении количества (там же).

Расценка проектного сборника имеет постоянные величины **A** и **B** — по ним считается стоимость проектирования (там же), т.е. формула вида `Цпр = (A + B·X)·Ki·Kоб·Kусл` ([ГК «Адепт», блог ПИР](https://gk-adept.ru/pir_blog/izmeneniya_v_zenoobrazovanii/stoimost_proektno_smetnoj_dokumentacii_kapitalnogo_remonta/)).

Стадии в проектном сборнике ГРАНД-Сметы маркируются тремя литерами: **П** — проектная документация, **РД** — рабочая документация, **РП** — рабочий проект; значения коэффициентов относительной стоимости и коэффициентов технической части даются отдельно по каждой стадии ([ГРАНД-Смета](https://help.grandsmeta.ru/dopolnitelnye-rezhimy/26-smety-na-proektno-izyskatelskie-raboty/normativnaya-baza-na-proektno-izyskatelskie-raboty/sbornik-na-proektnye-raboty)). Это подтверждает, что литеры `П / Р / РД / РП` в тексте обоснования — легитимный структурный токен, а не «мусор».

### 1.5. Regex-пригодные шаблоны

Даны в синтаксисе Python `re` с `re.IGNORECASE | re.UNICODE`. Перед применением — нормализация (см. раздел 7).

```python
# 0. Нормализация: NBSP→space, различные тире → '-', «№»→'N', ё→е, схлопывание пробелов
NBSP = "\u00a0\u202f\u2009"
DASH = "\u2010\u2011\u2012\u2013\u2014\u2015\u2212"

# 1. СБЦП, длинная форма: СБЦП 81-02-17-2001
RE_SBCP_LONG = r"СБЦ?П?\s*81\s*-\s*02\s*-\s*(?P<num>\d{1,2})\s*-\s*(?P<year>2001)"

# 2. СБЦП, короткая форма: СБЦП 81-2001-17
RE_SBCP_SHORT = r"СБЦ?П?\s*81\s*-\s*(?P<year>2001)\s*-\s*(?P<num>\d{1,2})"

# 3. Кодировка Адепт: СБЦП 81-02-17-2001_0-0-1-16  (суффикс = часть-глава-таблица-позиция)
RE_ADEPT = (r"СБЦП\s*81-02-(?P<num>\d{1,2})-2001"
            r"_(?P<part>\d+)-(?P<chapter>\d+)-(?P<table>\d+)-(?P<item>\d+)"
            r"(?:-(?P<sub>\d+))?")

# 4. Компактный код ГРАНД-Смета (ПИР): СБЦП19-5-1  / СБЦ19-5-1
RE_GRAND_PIR = r"(?P<pref>СБЦП|СБЦ|СЦ|СиЦ|СпЦ)\s*(?P<num>\d{1,2})\s*-\s*(?P<table>\d{1,3})\s*-\s*(?P<item>\d{1,3})(?:\s*-\s*(?P<sub>\d{1,3}))?"

# 5. Норматив затрат: НЗ №849/пр табл. 3.8 п.10   (варианты: «НЗ 849/пр, таблица 3.8, пункт 10»)
RE_NZ = (r"(?:НЗ|нормативн\w*\s+затрат\w*)?[\s,]*"
         r"(?:N|№|N?o?)?\s*(?P<order>\d{1,4})\s*/\s*пр"
         r"(?:[\s,;]*(?:табл\w*\.?|т\.)\s*(?P<table>\d+(?:\.\d+)*))?"
         r"(?:[\s,;]*(?:п\.|пункт\w*|поз\w*\.?)\s*(?P<item>\d+(?:[.-]\d+)*))?")

# 6. Любой приказ Минстроя/Минрегиона в обосновании: 707/пр, 1/пр, 854/пр, 421/пр
RE_ORDER = r"\b(?P<order>\d{1,4})\s*/\s*пр\b"

# 7. МРР Москвы: МРР-4.8.02-18, МРР-1.1.03-22, МРР-3.2.06.08-13, МРР 7.1-16
RE_MRR = (r"МРР\s*-?\s*(?P<chapter>\d{1,2})\.(?P<collection>\d{1,2})"
          r"(?:\.(?P<sub>\d{2}(?:\.\d{2})*))?"
          r"\s*-\s*(?P<year>\d{2})\b")

# 8. Текстовый алиас с годом: «СБЦ АСУТП 2016», «СБЦ Железные дороги 2014»
RE_ALIAS_YEAR = r"(?P<pref>СБЦП?|СБЦ)\s+(?P<name>[А-ЯЁа-яё\w\s\.\-«»\"]{3,80}?)\s*(?P<year>19\d{2}|20\d{2})\b"

# 9. Короткие алиасы вида СБЦ-1.5 / СБЦ-НДП-06 — разрешаются ТОЛЬКО словарём
RE_ALIAS_SHORT = r"\bСБЦ\s*-\s*(?P<tail>[А-ЯЁA-Z]{0,5}\s*-?\s*\d{1,2}(?:\.\d{1,2})?)\b"

# 10. Старые сборники цен: «Сборник цен ... Раздел 24», «Глава 20»
RE_OLD_COLLECTION = r"Сборник\s+цен[^\n]{0,60}?(?:Раздел|Глава)\s*(?P<sec>\d{1,2})"

# 11. Стадия в обосновании: П / Р / РД / РП / П+Р
RE_STAGE = r"(?<![А-ЯЁа-яё])(?P<stage>П\+Р|РП|РД|П|Р)(?![А-ЯЁа-яё])"

# 12. Интервал основного показателя: «от 1000 до 5000», «св. 1000 до 5000», «>1000»
RE_RANGE = r"(?:от|св\.?|свыше|более)\s*(?P<lo>[\d\s.,]+)\s*(?:до|-|—)\s*(?P<hi>[\d\s.,]+)"
```

Приоритет разбора (важно, иначе `RE_SBCP_SHORT` съест длинную форму): **3 → 1 → 2 → 4 → 7 → 5/6 → 8 → 10 → 9**. Оба варианта шифра СБЦП обязательно нормализуются к одному канону — рекомендую хранить канон в короткой форме `СБЦП 81-2001-NN`, поскольку сам первоисточник называет её «более коротким вариантом» и допускает оба ([NormaCS](https://www.normacs.info/answers/1206)).

### 3.2. Открытый JSON-API модуля ПИР (проверено 15.08.2026)

Отдельного документированного «открытого API» Минстрой не декларирует — **декларации не найдено**. Но SPA ФГИС ЦС обращается к обычным HTTP-эндпоинтам без авторизации, они отвечают JSON и доступны напрямую (`robots.txt` запрещает только `/data-storage/`):

| Эндпоинт | Что отдаёт |
|---|---|
| `GET /api/PirMethods` | Методики ПИР: иерархия (1.1 по изысканиям, 1.2 по проектным работам) + документы с `approvingActInfo`, `guid`, `frsnDocGuid`, `approvingActGuid` ([пример](https://fgiscs.minstroyrf.ru/api/PirMethods)) |
| `GET /api/SurveyWorkSn?periodId=426` | Сметные нормативы **на изыскания**: 6 разделов, 14 документов, с приказом, уровнем цен, индексом и `filePath` ([пример](https://fgiscs.minstroyrf.ru/api/SurveyWorkSn?periodId=426)) |
| `GET /api/SurveyDesignSn?periodId=426` | Сметные нормативы **на проектные работы**: 25 разделов, 93 документа ([пример](https://fgiscs.minstroyrf.ru/api/SurveyDesignSn?periodId=426)) |
| `GET /api/PirIndex` / `?periodId=NNN` | Индексы ПИР: иерархия по годам/кварталам (коды `4.25`, `4.2503`, `4.26`, `4.2602`…) + письма Минстроя с массивом `indexes` (`rtmPriceLevel`, `estimatedPriceSurveyDesignForBuildingIndex`, `estimatedPriceSurveyWorkForBuildingIndex`) ([пример](https://fgiscs.minstroyrf.ru/api/PirIndex)) |
| `GET /api/PirIndex/Periods` | Список периодов и активный: `{"items":[{"value":426,"text":"2 квартал 2026 г."},…],"activePeriodId":426}` ([пример](https://fgiscs.minstroyrf.ru/api/PirIndex/Periods)) |
| `GET /api/PirCalculationExamples?periodId=426` | 14 примеров расчётов (5.2 по изысканиям, 5.3 по проектным работам) с `filePath` ([пример](https://fgiscs.minstroyrf.ru/api/PirCalculationExamples?periodId=426)) |
| `GET /api/<entity>/Meta` | Метаописание колонок: `guid, parentGuid, name, approvingActInfo, approvingActGuid, rtmPriceLevel, index, filePath` (проверено на `SurveyDesignSn/Meta`, `SurveyWorkSn/Meta`, `PirIndex/Meta`, `PirMethods/Meta`) |
| `GET /api/values/GetFileContent/{guid}` | Сам файл норматива/письма (PDF и др.). Рабочий пример из поисковой выдачи: [Методическое пособие, guid 98e45dcb…](https://fgiscs.minstroyrf.ru/api/values/GetFileContent/98e45dcb-6a7a-44b9-84b8-03ba2d077840) |
| `GET /api/newsrss` | RSS новостей (объявлен в `<link rel="alternate">` в HTML ФГИС ЦС) |

Критично: **без параметра `periodId` эндпоинты `SurveyDesignSn` и `SurveyWorkSn` возвращают пустой ответ** `{"hierarchy":[],"documents":[]}`; с `?periodId=426` — полный реестр. `PirArchive` без параметров отдаёт HTML SPA. Внутренние перечисления из клиентского бандла: типы документов ФРСН `FrsnDoc=10, Act=20, FerDoc=30, FerChangeDoc=40, SnChangeDoc=41, FsscPgDoc=50, PirDoc=60`; виды ПИР-сущностей `PirMethods=110, SurveyWorkSn=120, SurveyDesignSn=130, PirIndex=140, CalculationExamples=150`; статусы `Draft=10, Actual=20, Arhive=30` (бандл [public.js](https://fgiscs.minstroyrf.ru/public.js?2b2204586d77da1c49b9)).

Готовый минимальный рецепт выгрузки:

```bash
P=$(curl -s https://fgiscs.minstroyrf.ru/api/PirIndex/Periods | python3 -c 'import sys,json;print(json.load(sys.stdin)["activePeriodId"])')
curl -s "https://fgiscs.minstroyrf.ru/api/SurveyDesignSn?periodId=$P" -o design.json
curl -s "https://fgiscs.minstroyrf.ru/api/SurveyWorkSn?periodId=$P"   -o survey.json
curl -s "https://fgiscs.minstroyrf.ru/api/PirIndex?periodId=$P"       -o index.json
```

Ограничения, которые надо учитывать: `PirIndex/Periods` на 15.08.2026 отдаёт максимум **2 квартал 2026 г.** (`activePeriodId=426`) — т.е. индексы III кв 2026 в модуль ПИР ещё не загружены, хотя письмо Минстроя уже вышло (см. раздел 6). Это недокументированный внутренний API: контракт может измениться без уведомления, поэтому в продакшене нужно версионировать парсер и держать fallback на xlsx-выгрузку ФРСН.

**Что искали и не нашли:** официальной XML- или CSV-выгрузки реестра ПИР, публичной документации API (Swagger/OpenAPI), заявленных «открытых данных» ФРСН по ПИР — **не найдено**.

## 4. XML-схемы Минстроя и форматы для экспертизы

### 4.1. Перечень схем: смет ПИР в нём нет

Действующие XML-схемы этапа изысканий и проектирования на странице Минстроя (обновление 09.04.2025): Задание на проектирование (09.04.2025), Заключение экспертизы (28.12.2024), Раздел № 1 ПД «Пояснительная записка» (28.12.2024), Ведомость объёмов работ (11.10.2024), Результаты конъюнктурного анализа (18.07.2024), Сводка затрат, Объектный сметный расчёт, Сводный сметный расчёт, ЛСР базисно-индексным методом, ЛСР ресурсно-индексным методом (все 18.07.2024), Сведения о типовой ПД (19.06.2023) ([Минстрой, «XML-схемы»](https://minstroyrf.gov.ru/tim/xml-skhemy/)). Реестр XML-схем — [minstroyrf.gov.ru/docs/419569/](https://minstroyrf.gov.ru/docs/419569/).

**XSD на формы 2П, 3П, 4П, 1ПС и на сводную смету ПИР в перечне отсутствуют — не найдено.** Новая схема «Пояснительная записка к сметной документации» опубликована 03.02.2026 и вступила в силу 03.05.2026 ([ЛОЭкспертиза](https://loexp.ru/tpost/zmsu3sbpc1-poyasnitelnaya-zapiska-k-smetnoi-dokumen)), но и она не относится к сметам ПИР.

Полномочие утверждать схемы — исключительно у Минстроя; обязательность XML установлена приказами Минстроя от 12.05.2017 № 783/пр (документация на экспертизу) и от 08.06.2018 № 341/пр (заключение экспертизы), а также постановлением Правительства РФ от 15.09.2020 № 1431 ([Главгосэкспертиза, «Что важно знать о XML»](https://gge.ru/vazhno-o-xml/)).

### 4.2. Пункт 3 приказа 783/пр — что подавать при отсутствии XSD

Дословно из текста Требований (приказ Минстроя от 12.05.2017 № 783/пр):

> «2. Для получения услуг электронные документы представляются в виде файлов в формате xml (за исключением случаев, установленных пунктом 3 настоящих Требований). Схемы… размещаются на официальном сайте Министерства… и вводятся в действие по истечении трех месяцев со дня размещения.»

> «3. В случае если на официальном сайте Министерства отсутствует xml-схема… электронные документы представляются в следующих форматах:» — **а)** `doc, docx, odt` для текстовых документов без формул; **б)** `pdf` для текстовых документов с формулами и/или графикой и для графических документов; **в)** `xls, xlsx, ods` — «для документов, содержащих сводки затрат, сводного сметного расчета стоимости строительства, объектных сметных расчетов (смет), локальных сметных расчетов (смет), **сметных расчетов на отдельные виды затрат**» ([docs.cntd, приказ 783/пр от 25.08.2017](https://docs.cntd.ru/document/456075299/titles/65C0IR)).

Вывод для смет ПИР: поскольку XSD на формы ПИР нет, они подпадают под п.3 «в» — **xlsx/xls/ods** (сметы на ПИР по своей природе — сметные расчёты на отдельные виды затрат), а при формульно-текстовом содержании — pdf по п.3 «б». Официального разъяснения Минстроя именно по формам 2П/3П/4П/1ПС **не найдено**; общее разъяснение о действиях при отсутствии XML-схемы — [infras.ru, 12.05.2025](https://infras.ru/news/tpost/8ms2j64pd1-chto-delat-esli-xml-shemi-na-saite-minst) и [infras.ru, 18.10.2024](https://infras.ru/news/tpost/pidhsakh71-minstroi-razyasnil-chto-delat-v-sluchae).

### 4.3. Практика ЕЦПЭ / Главгосэкспертизы

С 01.08.2023 сметная документация принимается на ЕЦПЭ **только в XML** — по требованиям к форматам загружаемых файлов ([Минстрой, пресс-релиз](https://minstroyrf.gov.ru/press/xml-format-stal-obyazatelnym-dlya-priema-smet-na-ekspertizu/); [СПб ГАУ «ЦГЭ», 25.07.2023](https://www.spbexp.ru/press-tsentr/news/ekspertiza-smet-tolko-v-xml-formate/); [engeostroy.ru, 04.08.2023](https://engeostroy.ru/sro/xml-format-stal-obyazatelnym-dlya-priema-lokalnyh-smetnyh-raschetov-dlya-proizvodstva-ekspertizy/)). Но это требование распространяется на те документы, для которых схемы утверждены. Региональная практика прямо предписывает **дублирование**: «Сметную документацию представлять одновременно в табличном формате (*.xlsx), в формате программного комплекса (*.xml), а также… в формате схемы электронных документов (*.gge)» ([КГБУ «Крайгосэкспертиза», Хабаровский край](https://expert-khv.ru/poryadok-provedeniya-gosudarstvennoy-ekspertizy-v-elektronnom-vide-cherez-edinuyu-cifrovuyu)). Более старые требования (приказ от 21.11.2014) прямо называли для сводного сметного расчёта рекомендуемый `*.xlsx` и допустимые `*.pdf` (с возможностью копирования текста) и `*.xml` (ПК «ГРАНД-Смета») ([docs.cntd 420225349](https://docs.cntd.ru/document/420225349)).

Технически ГГЭ принимает пакет `.gge` — zip-архив с несколькими файлами, формируемый по XML-схемам ([ГРАНД-Смета, «Что нового в версиях»](https://www.grandsmeta.ru/whatisthenewversion)); версия «ГРАНД-Смета» 2024.3 (18.10.2024) перешла на XML-схемы версии 3.01, опубликованные 18.07.2024 ([ГСНР](https://www.gsnr.ru/smetchiku/novosti/115-novaya-versiya-grand-smeta-2024-3), [i-tat.ru](https://its.i-tat.ru/articles/vypushchena-novaya-versiya-grand-smety-20243-chto-izmenilos)).

**Ответ на вопрос задания:** сметы ПИР в XML по схемам Минстроя **не принимаются, потому что таких схем нет**; фактический формат — xlsx (+pdf), а XML/gge применяется к ССР/ОСР/ЛСР строительства. Прямого письма ГГЭ/ЕЦПЭ с формулировкой «сметы ПИР — только xlsx» **не найдено**.

## 5. Коэффициенты ПИР

### 5.1. Стадийность (в терминологии Адепт — Ки1 / Кст)

Обозначение «**Ки1**» в нормативных документах Минстроя **не найдено** — это внутренняя нотация сметных ПК. Нормативная основа стадийности:

- **По СБЦ/СБЦП:** «распределение базовой цены на разработку проектной и рабочей документации осуществляется, как правило, в соотношении **ПД — 40 %, РД — 60 %**, и может уточняться по согласованию между исполнителем и заказчиком» — п. 1.4 Методических указаний по применению СБЦ (приказ Минрегиона № 620 от 30.12.2009) ([ГК «Адепт», разбор Методических указаний](https://gk-adept.ru/pir_blog/voprosy_sostavleniya_i_proverki_smet/osobennosti_metodicheskih_ukazanij_po_primeneniyu_sbc/)). Главгосэкспертиза подтверждает: «Распределение базовой цены на разработку проектной и рабочей документации осуществляется в соответствии с показателями, приведенными в таблице 1 Методических указаний, и может уточняться по согласованию между исполнителем и заказчиком» ([ГГЭ, вопрос-ответ, 24.12.2018](https://gge.ru/services/questions/2621/3558/)).
- **Пропорция задаётся каждым справочником индивидуально**, значения 40/60 не универсальны: СБЦП 81-2001-17 «Объекты водоснабжения и канализации» — **П 60 / Р 40** ([Меганорм](https://meganorm.ru/mega_doc/norm/normativy/0/sbtsp_81-2001-17_sbtsp_81-02-17-2001_gosudarstvennyy_smetnyy.html)); СБЦП 81-2001-03 «Объекты жилищно-гражданского строительства» — **П 40 / Р 60** ([stroyinf](https://files.stroyinf.ru/Data2/1/4293817/4293817119.htm)). Это ключевой момент: **нельзя хардкодить 0,4/0,6** — надо брать значение из конкретного справочника.
- **По НЗ:** согласно **п. 124 Методики 707/пр** величину коэффициента стадийности следует определять на основании норматива затрат (НЗ); таблица 1.1 Общих положений НЗ на сети ИТО и объекты инфраструктуры даёт П = 40 %, Р = 60 %, П+Р = 100 % ([ГК «Адепт»](https://gk-adept.ru/pir_blog/pir_rubrika_vopros-otvet/stadii_v_normativnyh_zatratah_nz_uchest_koefficient_stadijnosti/)).
- **С информационной моделью пропорция инвертируется:** таблица 2.3 того же НЗ даёт **П = 60 %, Р = 40 %** для документации с ИМ; а если ИМ разрабатывается только на стадии РД (пример — НЗ на объекты газовой промышленности, 849/пр): «Стоимость работ по подготовке рабочей документации, содержащей материалы в форме информационной модели… определяется в размере **60 процентов** от стоимости проектных работ, определенной по ценам таблиц 3.1–3.9 главы III НЗ», и сумма коэффициентов стадийности при этом может не равняться 100 % ([ГК «Адепт»](https://gk-adept.ru/pir_blog/pir_rubrika_vopros-otvet/stadii_v_normativnyh_zatratah_nz_uchest_koefficient_stadijnosti/)).
- **Стадия «РП» (рабочий проект)** как отдельная градация с полным коэффициентом 1 существует в структурах данных проектных сборников: коэффициенты относительной стоимости и коэффициенты технической части даются отдельно для П / РД / **РП** ([ГРАНД-Смета](https://help.grandsmeta.ru/dopolnitelnye-rezhimy/26-smety-na-proektno-izyskatelskie-raboty/normativnaya-baza-na-proektno-izyskatelskie-raboty/sbornik-na-proektnye-raboty)). Прямого нормативного текста «РП = 1,0» **не найдено**; практическое разъяснение: если РД разрабатывается в одну стадию по нормам проектирования без разработки ПД, «в расчет вводится коэффициент 0,6 для проектных работ в одну стадию "РД"» ([NormaCS, ответ 2174, 01.11.2017](https://www.normacs.info/answers/2174)).
- Постановление Правительства РФ от 16.02.2008 № 87 названо основным документом, регламентирующим распределение проектных задач по стадиям ([ГК «Адепт»](https://gk-adept.ru/pir_blog/voprosy_sostavleniya_i_proverki_smet/stadii_proektirovaniya_pereschet_koehfficienta_stadijnosti/)).
- Формула стадийности для линейных объектов при разной категории сложности участков трассы: `Кст = L1/…` — приведена в разборе СБЦП «Коммунальные инженерные сети и сооружения» ([ГК «Адепт»](https://gk-adept.ru/pir_blog/proektnye_raboty/osobennosti_spravochnika_kommunalnye_inzhenernye_seti_i_sooruzheniya_chast_3/)).

### 5.2. Типы коэффициентов и правила их арифметики (нормативно, 707/пр)

Это самый важный блок для программной реализации: правила отличаются по типу коэффициента, а **«ни в одном нормативном документе ни один коэффициент не промаркирован»** — тип определяет сметчик, и в «АДЕПТ: ПРОЕКТ» типизация выполнена на основе Методических указаний и разъяснений ЦЕНТРИНВЕСТпроекта ([ГК «Адепт», «Коэффициенты в проектировании»](https://gk-adept.ru/pir_blog/adept_proekt_otvety_na_tehnicheskie_voprosy/koehfficienty_v_proektirovanii/)).

Нормативные правила — **п. 171 Методики 707/пр**:
1. при применении нескольких корректирующих коэффициентов, учитывающих **усложняющие** факторы, общий коэффициент = **единица плюс сумма дробных частей** каждого коэффициента;
2. если применяются несколько коэффициентов, размеры которых меньше и (или) больше единицы, а также общий корректирующий коэффициент, — общий коэффициент определяется **перемножением** ([Контур.Норматив, текст 707/пр](https://normativ.kontur.ru/document?moduleId=1&documentId=506004)).

Прочие нормативные положения 707/пр (там же):

| Пункт | Содержание |
|---|---|
| подп. «д» п. 15 | при наличии усложняющих/упрощающих факторов в составе НЗ предусматриваются корректирующие коэффициенты, разрабатываемые по пп. 78–81 |
| п. 78 | коэффициент = соотношение стоимостных показателей двух объектов-представителей (с фактором и без) |
| п. 79 | если трудоёмкость не выражается через стоимость — расчёт по трудозатратам (пп. 101–111), соотношение даёт **дробную часть** коэффициента |
| п. 80 | при невозможности расчёта — размер принимается по действующему сметному нормативу из ФРСН при наличии аналогичного фактора |
| п. 81 | если фактор влияет только на отдельные разделы ПД/комплекты РД — коэффициент устанавливается к цене **этих разделов**, определяемой по процентному распределению цены проектных работ в НЗ |
| п. 130, п. 135 | при отсутствии условий, требующих коэффициентов, коэффициент принимается равным **1** |

### 5.3. Понижающие коэффициенты и коэффициенты для «малых» объектов (Кпон)

Термин «**Кпон**» в нормативных источниках **не найден**. Фактические механизмы:
- **Привязка типовой/повторно применяемой ПД:** «Базовая цена проектных работ с использованием проектной документации повторного или массового применения («привязка») определяется по ценам Справочника с применением **понижающего коэффициента** по согласованию с заказчиком в зависимости от трудоемкости работ» — п. 1.11 СБЦ ([ruscable, текст СБЦ](https://www.ruscable.ru/info/snip/Data1/5/5246/index.htm)).
- **Отклонение основного показателя более чем на 50 %** от табличных значений (это и есть случай «малых»/«крупных» объектов): по п. 2.3 «Порядка определения базовой цены проектных работ» Сборника допускается применять специальные коэффициенты ([Инфострой](https://gk-infostroy.ru/spravka/pir/raschet_po_p_2_3__poryadka_opredeleniya_bazovoj_tseny_proektnykh_rabot.htm)); отдельный порядок расчёта при отклонении основного показателя разъяснён письмом ОАО «ЦЕНТРИНВЕСТпроект» от 06.07.2011 № 391-03/4 ([ООО «Атлон», консультации](https://ooo-atlon.ru/katalog1/programmy_dlya_proektno-izyskatel_nyh_rabot/vopros-otvet/konsul_tacii_po_cenoobrazovaniyu_v_proektirovanii/)).
- **Выбор площадки (трассы):** «Стоимость работ по выбору площадки (трассы) для строительства определяется по ценам на разработку проекта соответствующего объекта с коэффициентом **0,05**» ([Указания по применению цен, stroyinf](https://files.stroyinf.ru/Data2/1/4294845/4294845477.htm)).

### 5.4. Районный коэффициент

Ключевое правило — районный коэффициент начисляется **не на всю цену, а на долю оплаты труда**: «при определении стоимости проектных работ в соответствии с калькуляцией затрат районный коэффициент учитывается дополнительно в формуле (3.13) Методики при определении общих затрат на оплату труда исполнителей в строке "Итого оплата труда" **формы № 3п**» ([Контур.Норматив, 707/пр](https://normativ.kontur.ru/document?moduleId=1&documentId=506004)). Практическое разъяснение: «Районный коэффициент определяется от доли ЗП в стоимости проектных работ, эта доля определяется коэффициентом **0.6839**, и только на эту часть начисляется районный» ([Всё о сметах, 17.01.2022](https://www.all-smety.ru/company/news/novaya-metodika-opredeleniya-stoimosti-rabot-po-podgotovke-proektnoy-dokumentatsii/)). Структура стоимости проектных работ (приложение № 2 к 707/пр), где приведена доля зарплаты в себестоимости, — [Инфострой, приложение 2](https://gk-infostroy.ru/spravka/pir/prilozhenie_2_2.htm). Формула калькуляции: `Спр = Вср × Тп × Чобщ × Ккв-уч`, где `Ккв-уч` — степень участия исполнителей разной квалификации ([пример на ФГИС ЦС](https://fgiscs.minstroyrf.ru/frsn/reference/letters/59747d94-f106-4d03-93b9-971cdf50a4bf)).

Также в 707/пр применяется норматив «альфа» — «процентное отношение стоимости проектных работ для объектов капитального строительства непроизводственного назначения и линейных объектов» ([sudact, текст 707/пр](https://sudact.ru/law/prikaz-minstroia-rossii-ot-01102021-n-707pr/)); соответствующая формула в старых базах: `Цпр = Сстр 2001 × α/100 × Ктек × Кст` ([материалы Адепт, DOC](https://www.all-smety.ru/upload/iblock/584/previous_adept.doc)).

## 7. Алгоритмы нечёткого сопоставления текстовых обоснований со справочником

Публичной документации на алгоритмы сопоставления внутри «ГРАНД-Смета» / «Адепт: Проект» **не найдено**. Ниже — практическая схема, где каждый компонент опирается на источник.

### 7.1. Приоритет структурных полей над текстом

Это главный принцип, вытекающий не из ИТ-литературы, а из структуры самих данных: расценка ПИР однозначно адресуется набором «часть / глава / таблица / позиция + диапазон значений основного показателя», и все эти поля хранятся в нормативной базе отдельно от наименования ([ГРАНД-Смета](https://help.grandsmeta.ru/dopolnitelnye-rezhimy/26-smety-na-proektno-izyskatelskie-raboty/normativnaya-baza-na-proektno-izyskatelskie-raboty/sbornik-na-proektnye-raboty)). Поэтому пайплайн должен быть каскадным:

1. **Точный ключ:** нормализованный шифр справочника (канон `СБЦП 81-2001-NN`, оба варианта эквивалентны по [NormaCS](https://www.normacs.info/answers/1206)) + таблица + пункт. Совпало → сопоставление достоверное, нечёткие метрики не запускаются.
2. **Ключ приказа:** для НЗ — `NNN/пр` + таблица + пункт (структура «таблицы 3.1–3.19 главы III НЗ», [ГК «Адепт»](https://gk-adept.ru/pir_blog/pir_rubrika_vopros-otvet/stadii_v_normativnyh_zatratah_nz_uchest_koefficient_stadijnosti/)).
3. **Проверка периода и уровня цен:** норматив может быть отменён или заменён (812/пр отменил 221/пр; 848/пр рекомендован вместо СБЦП 81-2001-03 по [NormaCS](https://normacs.net/Doclist/doc/257VT.html)). Валидация делается по реестру ФГИС ЦС на нужный `periodId` (раздел 3).
4. **Только затем** — нечёткое сопоставление по наименованию и разрешение алиасов по словарю.

### 7.2. Нормализация и токенизация (обязательный препроцессинг)

Специфика русских сметных обоснований: неразрывные пробелы, разные виды тире, «№» vs «N», «табл.»/«таблица»/«т.», «п.»/«пункт»/«поз.», ё/е, разный регистр, перестановка групп в шифре (длинная/короткая форма), написание года через пробел. Всё это снимается детерминированной нормализацией **до** любых метрик — иначе расстояние Левенштейна будет мерить типографику, а не смысл.

### 7.3. Метрики сходства

- **Расстояние Левенштейна** — минимальное число операций вставки, удаления и замены единичной стоимости для преобразования одной строки в другую ([Журнал «Программные продукты и системы»](https://www.swsys.ru/index.php?page=article&id=2559)). Хорошо работает на коротких кодах и опечатках, плохо — на длинных наименованиях с перестановкой слов.
- **Дамерау–Левенштейна, Джаро–Винклера, Хэмминга** — сопоставительный анализ этих метрик для задач сравнения строк: [Вестник ВГУ, «Выбор варианта из множества решений при нечетком…», 29.09.2023](https://journals.vsu.ru/sait/article/view/11428); обзор применимости метрик Хэмминга/Левенштейна/Дамерау–Левенштейна и метода N-грамм при работе с несколькими источниками данных: [«Молодой учёный», № 361](https://moluch.ru/archive/361/80785/).
- **Триграммы (n-граммы).** «Триграммное сходство (trigram similarity) между двумя строками определяется числом совпадающих символьных триплетов» ([morfoedro.art, «Алгоритмы приблизительного сравнения текста»](https://morfoedro.art/ru/articolo/223)). Промышленная реализация — `pg_trgm` в PostgreSQL: «модуль предоставляет функции и операторы для определения схожести алфавитно-цифровых строк на основе триграмм, а также классы операторов индексов, поддерживающие быстрый поиск схожих строк» ([PostgreSQL docs, F.35](https://www.postgresql.org/docs/current/pgtrgm.html); [русская версия](https://postgrespro.ru/docs/postgresql/current/pgtrgm)). Триграммный индекс (GiST/GIN) — единственный способ сделать нечёткий поиск по большому справочнику быстрым, а не O(N) по всем расценкам ([PostgreSQL docs](https://www.postgresql.org/docs/current/pgtrgm.html)).
- **TF-IDF.** Готовой функции TF-IDF-сходства строк в PostgreSQL нет, обсуждение сводит задачу к `pg_trgm` ([Stack Overflow, 10.03.2022](https://stackoverflow.com/questions/71422599/tf-idf-string-similarity-function-for-postgresql)). Практический смысл TF-IDF в нашей задаче — **взвешивание токенов**: слова «объекты», «строительство», «работы» встречаются почти в каждом наименовании справочника и не должны влиять на ранжирование, а «медеэлектролитные», «АСУТП», «гидрографические» — должны.
- **Быстрые библиотеки:** `rapidfuzz-cpp` — SIMD-оптимизированная библиотека, реализующая метрики Левенштейна, Дамерау–Левенштейна, Хэмминга, Indel, Джаро и Джаро–Винклера ([Linux.org.ru, 18.04.2023](https://www.linux.org.ru/news/opensource/17197392)).
- **Нечёткий поиск подстроки/индексация:** обзор задачи нечёткого сопоставления строк и алгоритмов индексации — [AlgoList, «Нечеткий поиск»](https://algolist.ru/search/fsearch/index.html); вариант `pg_trgm` для нечёткого поиска подстрок — [обсуждение в pgsql-hackers, 18.12.2015](https://www.postgresql.org/message-id/567461EC.4030803@postgrespro.ru).

### 7.4. Рекомендуемая архитектура сопоставления

1. Нормализация → извлечение структурных полей по regex из раздела 1.5 → каскад точных ключей (§7.1).
2. Кандидаты по триграммному индексу (`pg_trgm`, порог `similarity` подбирается по валидационной выборке) — сужение до 20–50 кандидатов ([PostgreSQL docs](https://www.postgresql.org/docs/current/pgtrgm.html)).
3. Переранжирование кандидатов взвешенной суммой: `w1·(совпадение шифра) + w2·(совпадение таблицы/пункта) + w3·(TF-IDF cosine по наименованию) + w4·(1 − нормированный Левенштейн) + w5·(попадание количества в диапазон значений расценки)`. Последний признак уникален для ПИР и очень силён: диапазон основного показателя хранится у каждой единичной расценки, и по нему программа сама перевыбирает расценку ([ГРАНД-Смета](https://help.grandsmeta.ru/dopolnitelnye-rezhimy/26-smety-na-proektno-izyskatelskie-raboty/normativnaya-baza-na-proektno-izyskatelskie-raboty/sbornik-na-proektnye-raboty)).
4. Валидация по реестру ФГИС ЦС: действует ли норматив на нужный `periodId`, совпадает ли уровень цен и индекс с тем, что в смете (§3.2, §6.4).
5. Три исхода: `matched` (точный ключ), `probable` (score выше верхнего порога), `manual` (в очередь на ручное разрешение — прежде всего короткие алиасы `СБЦ-1.5`, `СБЦ-НДП-06`, для которых публичного определения нет).
