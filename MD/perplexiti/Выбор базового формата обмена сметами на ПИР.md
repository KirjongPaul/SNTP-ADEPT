# Выбор базового формата обмена сметами на ПИР

Документ решения по трём кандидатам: XML Минстроя (`.gge`), XML ГРАНД-Сметы, внутренний контур «Адепт: Проект» (Excel/буфер обмена). Основание — официальная справка ПК «Адепт» версии 2026.4 (файл `AUS_HELP.PDF`, 1378 стр.), нормативные акты Минстроя и письма ФАУ «Главгосэкспертиза России», справка ГРАНД-Сметы и страницы ГК «Адепт».

Дата подготовки: 15.08.2026. Все утверждения ниже подтверждены ссылками; там, где источник не найден, прямо написано «не найдено».

## 1. Краткий вывод

| Кандидат | Годится как базовый формат для ПИР | Решающий факт |
|---|---|---|
| **XML Минстроя `.gge`** | **Нет** | Схемы для смет на ПИР (2П/3П/4П/1ПС) не разработаны; требование XML на ПИР не распространяется — письмо ФАУ «Главгосэкспертиза России» от 23.06.2023 № 01-01-15/10109-СЛ ([Контур.Норматив](https://normativ.kontur.ru/document?moduleId=8&documentId=452801)) |
| **XML ГРАНД-Сметы** | **Нет как основной, да как вспомогательный** | XSD проектной сметы ПИР на [xsd.grandsmeta.ru](https://xsd.grandsmeta.ru/) отсутствует; у макрокоманды `ExportToXml` перечень типов документов не приведён, тогда как у `ExportToExcel` ПИР указан прямо ([справка ГРАНД-Сметы](https://help.grandsmeta.ru/tekhnicheskij-razdel/programmirovanie-makrosov/makrokomandy/dopolnitelnye-makrokomandy)) |

Практический вывод: **базовым носителем данных должен быть наш собственный канон (PIR-IR) с выгрузкой в XML-каталог**, а обмен с «Адептом» строить через Excel-таблицы фиксированной раскладки и буфер обмена. XML Минстроя резервируется только для случая, когда сметы ПИР попадут в состав документов ЕЦПЭ как итоговая строка сводного расчёта.

## 2. XML Минстроя (`.gge`): что это

**Юридическая природа.** «XML Минстроя» — не название формата, а требование п. 2 приказа Минстроя России от 12.05.2017 № 783/пр представлять документы в формате XML по схемам, размещённым на сайте министерства; схема становится обязательной через 3 месяца после публикации ([Техэксперт](https://docs.cntd.ru/document/456075299/titles/65C0IR)). Для сметной документации обязательность введена поэтапно: с 18.08.2021 — локальные сметные расчёты, с 01.08.2023 — вся сметная документация, подаваемая через ЕЦПЭ ([Главгосэкспертиза](https://gge.ru/vazhno-o-xml/), [Минстрой России](https://minstroyrf.gov.ru/press/xml-format-stal-obyazatelnym-dlya-priema-smet-na-ekspertizu/)).

**Технически.** `.gge` — файл XML в кодировке UTF-8 с корневым элементом `Construction`; составной документ передаётся zip-архивом из нескольких `.gge` ([справка ГРАНД-Сметы](https://help.grandsmeta.ru/ob-ekty-i-smety/eksport-smet-v-razlichnye-formaty/eksport-v-format-gge), [grandsmeta.ru](https://www.grandsmeta.ru/whatisthenewversion)).

**Версия `v3_01`**, упомянутая в справке «Адепта» («загружаются только сметы РИМ схемы v3_01»), — версия сметных схем ресурсно-индексного метода, опубликованная 18.07.2024 и введённая в действие 18.10.2024 (`LocalEstimateResourceIndexMethod-3_01.xsd`); по конъюнктурному анализу действует уже версия 4.02 с 09.09.2025 ([ПравдаОСРО](https://pravdaosro.ru/construction/minstroy-pomenyal-xml-skhemu-dlya-rezultat/)).

## 3. Почему `.gge` не подходит для ПИР

1. **Прямое разъяснение экспертизы.** Письмо ФАУ «Главгосэкспертиза России» от 23.06.2023 № 01-01-15/10109-СЛ: «требование о предоставлении сметных расчетов в формате XML в настоящее время не распространяется на сметы на проектно-изыскательские работы» ([Контур.Норматив](https://normativ.kontur.ru/document?moduleId=8&documentId=452801)).
2. **Схем нет.** XSD на формы 2П, 3П, 4П, 1ПС и сводный расчёт стоимости ПИР на странице XML-схем Минстроя отсутствуют; официальной XML- или CSV-выгрузки ФРСН по ПИР также нет. Поэтому действует п. 3(в) приказа 783/пр — представление в xls/xlsx/ods; «формат gge для проектных смет Главгосэкспертизой не разработан» ([k-css.ru](https://k-css.ru/grand-smeta-eksport-import/p/3)).
3. **Модель данных не вмещает расчёт по СБЦ.** В схеме ЛСР коэффициент описан набором «Name + Reason + Num + Value», итог — элементом `Final`; параметров формулы, натурального показателя и структурированной ссылки на сборник базовых цен в схеме нет ([описание формата](https://www.i-tat.ru/file/filemanag/4c5c3ccb314b09adbc2090c19f59b680.pdf), [письмо ГГЭ № 20-05-1/12731-СГ](https://base.garant.ru/412526716/)). Расчёт вида \((A + B \cdot X_{\text{зад}}) \cdot N \cdot K_{\text{тек}} \cdot K_{\text{ст}}\) в такую структуру уложить нельзя — сохранится только итоговая сумма.
4. **Новая схема 2026 года не меняет картину.** XML-схема «Пояснительная записка к сметной документации» опубликована 03.02.2026 и обязательна с 03.05.2026, передаётся только в `.gge`, но ПИР присутствует в ней одной итоговой строкой «прочие расходы, включая ПИР», а не формами 2П/3П/4П ([XMLONLINE](https://xmlonline.ru/novosti/poyasnitelnaya-zapiska-k-smetnoj-dokumentacii-novyj-xml-dokument-uzhe-v-xmlonline-ru), [Госэкспертиза Новгородской области](https://gosexpert53.ru/news/na_sayte_minstroya_rossii_03_02_2026_razmeshchena_xml_skhema_poyasnitelnoy_zapiski_k_smetnoy_dokumen/)).

**Где `.gge` всё-таки нужен.** Если объект идёт через ЕЦПЭ, стоимость ПИР попадает в сводный сметный расчёт как строка главы 12 через `TCalculation/Link`. Значит наш модуль должен уметь отдать **итоговую сумму по сводной смете ПИР** в разрезе, пригодном для ручного переноса в ССР, но не претендовать на выгрузку самих форм 2П.

## 4. Почему XML ГРАНД-Сметы не может быть базовым

- В каталоге опубликованных схем [xsd.grandsmeta.ru](https://xsd.grandsmeta.ru/) присутствуют локальная смета, объектная/сводная, сметный контракт, конъюнктурный анализ, ведомость объёмов, пользовательский сборник, а также GGE 4.02/3.01 и MGE — **схемы проектной сметы ПИР среди них нет**.
- `Document.DocType = 9` = «Проектная смета (dtProjectSmeta)» в справке ГРАНД-Сметы подтверждается, но GUID `{39200715-3435-47E0-8C27-68A028AD6D25}` и идентификатор `sdtProjectSmeta` в открытых источниках **не найдены** — то есть строить экспорт «наугад» под неопубликованную схему нельзя.
- Элементы, необходимые для ПИР (`A`, `B`, `Xmin`, `Xmax`, таблица ставок СБЦ, относительные коэффициенты), в опубликованных схемах отсутствуют.
- Со стороны «Адепта» импорт «Загрузить смету из Гранд (*.xml)» описан только в модуле СМЕТА (справка, разд. 3 «Импорт / Экспорт», стр. 331–336). Для модуля ПРОЕКТ такого пункта в справке нет.

Вспомогательная роль остаётся: если заказчик пришлёт смету ГРАНД по СМР, наш парсер должен её прочитать — но это отдельный, не ПИР-контур.

## 5. Что реально умеет «Адепт: Проект» (по справке 2026.4)

| Возможность | Статус по справке | Ссылка в справке |
|---|---|---|
| Импорт смет ПИР из файла (любой формат) | **не описано** | — |
| Импорт Excel | только справочник «Должности» | разд. 3.11, стр. 939 |
| Импорт XML ГРАНД / АРПС / `.cxa` / `.gge` | только модуль СМЕТА | разд. 3, стр. 331–336 |
| Буфер обмена | внутренний, между сметами программы; при вставке расценка «принимает стадийность новой сметы и соответствующие стадии сметы РПД» | разд. 6.1, стр. 1034 |
| Вывод в Excel / Word | да; печать 2П комплексной и расчёта ГГЭ «возможна только в редакторе MS Excel» | разд. 12, 18 |
| Горячие клавиши `Ctrl+U` / `Ctrl+T` | **в справке отсутствуют** (Ctrl задокументирован лишь как мультивыбор в справочнике «РПД для группировки», стр. 934) | разд. 3.7 |

Отсюда архитектурное следствие: **интеграция с «Адептом» строится на Excel-раскладке и буфере обмена**, а не на файловом обмене. Наш модуль должен формировать таблицу, максимально совпадающую с бланком 2П (707/пр) по колонкам, чтобы вставка в «Адепт» проходила без ручной правки.

## 6. Принятое решение по архитектуре обмена

1. **Внутренний канон PIR-IR** (наш JSON/SQL) — единственный источник истины. Из него генерируются все выгрузки.
2. **XML-каталог сводных смет** — собственная схема, версионируемая, с полями обоснования, ставок A/B/X, коэффициентов с ролями и итогов. Хранение справочников — SQL.
3. **Выгрузка для «Адепта»** — Excel-раскладка бланка 2П (707/пр) + вариант «в буфер обмена» (XML Spreadsheet, единственный формат буфера, который несёт формулы в `ss:Formula`).
4. **Чтение входящих** — Excel (все пять выявленных диалектов книги V3.2), плюс XML ГРАНД по СМР как вспомогательный вход.
5. **`.gge`** — только на уровне итоговой суммы для сводного сметного расчёта; форм 2П в `.gge` не формируем, пока Минстрой не опубликует схему.

## 7. Открытые вопросы

1. Читает ли «Адепт: Проект» XML ГРАНД-Сметы фактически (в справке пункта нет) — проверяется только экспериментом на установленной копии `C:\Adept\AUS-client\adept_us.exe`.
2. Опубликует ли Минстрой XSD на формы 2П/3П/4П — отслеживать страницу XML-схем и новости Главгосэкспертизы.
3. Точная раскладка колонок, которую «Адепт» принимает из буфера в форму 2П — в справке для ПИР не документирована.
