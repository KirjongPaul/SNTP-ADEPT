# SNTP-ADEPT — план приложения Excel → Адепт:Проект

Дата: 2026-08-14 (дополнено 2026-08-15: ревизия Excel V3.2 и `.apr` — см. `02_REVISION.MD`)  
Статус: рабочий контур PIR-IR + XML Гранда + импорт Excel V3.2 (формулы ROUND) + снимок справочника `.apr`  
Целевой продукт: десктоп-приложение Windows, **весь диалог в WebView2**  
Пилот Excel: `MD/Сметы_Степновская ПХГ_РД_V3.2_Этап 3.xlsx` (V2.2 только архив)  
Пилот Гранд: `MD/Проектная смета.xml` + `.gsfx` (Гранд-Смета 16.2.1, тип «проектная смета»)  
Локальный Адепт: `C:\Adept\AUS-client\adept_us.exe` **2026.4.1.15**, лицензия до 30.06.2027; подключены только **Адепт: СЭД** и **Адепт: Проект** (нет модуля «Адепт: Смета»)

---

## 1. Задача

Сейчас сметы на ПИР (проектно-изыскательские работы), включая сводную смету, считаются и оформляются в Excel. Нужно научиться **преобразовывать этот Excel в формат, который принимает «Адепт:Проект»** (https://gk-adept.ru/programmy/adept_proekt1/).

Приложение:

- весь UI — внутри WebView2 (не WinForms/WPF-диалоги, кроме системных Open/Save);
- читает книгу Excel со сводом и локальными сметами 2П/3П;
- разбирает шапку, позиции, обоснования (НЗ/СБЦ), коэффициенты, формулы, итоги;
- показывает дерево объекта и отчёт сопоставления;
- выгружает канонический JSON (PIR-IR) и **XML проектной сметы Гранда** (без `GrandSmetaSign`); пакет CXA/toaus в Адепт — отдельный этап.

**Ключевое ограничение.** «Формат Адепт» для ПИР — это не «положить те же цифры в XML». «Адепт:Проект» **пересчитывает** позицию по справочнику (НЗ / СБЦ / МРР), формуле (A+B·X, интерполяция, экстраполяция), коэффициентам стадийности, районным и ведомственным. Цель конвертера — перенести **модель расчёта** (обоснование + параметры + коэффициенты), а не только итоговые рубли. Итоги Excel — контрольные суммы для сверки.

## 2. Выбранный стек

Выбор под Windows, WebView2, тяжёлый Excel и локальную работу со сметами без облака.

## 3. Что такое «Адепт:Проект» (факты с сайта)

Источник: https://gk-adept.ru/programmy/adept_proekt1/ и https://gk-adept.ru/programmy/adept_proekt/

- Профессиональный расчёт и проверка стоимости ПИР.
- База: ~300 действующих СБЦ/МРР, ведомственные сборники, НЗ (в т.ч. изыскания), МРР для Москвы.
- Методики: 707/пр (проектные работы), 1/пр (изыскания), 854/пр (ИМ/ТИМ), формы **2П (707), 3П, 4П**.
- Сводная смета: на сайте чаще упоминают форму **431/пр**. В установленном клиенте печатный шаблон `Sstylesheet.xsl` явно выводит **«Форма 1пс»** — та же форма, что в пилотном Excel Степновская. Есть и отраслевые своды (Роснефть `SRosneftAllColumns.xsl`, РЖД).
- Отраслевые формы: Роснефть **2П, 3П, 1ПС**; также РЖД, Транснефть, коэффициенты Газпром; отдельные печатные формы АСУТП.
- СЭД — модуль хранения/согласования внутри того же клиента `adept_us.exe`, не публичный REST API.
- На этой машине уже стоит полный клиент **Адепт:Управление строительством** с модулем **ПРОЕКТ** (справка, стр. 897–1158). Отдельная демоверсия для эталона не обязательна: эталон `.cxa` можно снять из `C:\Adept\AUS-client`.
- Контакты: 8 800 333-27-17. Страница «Для интеграторов» на 2026-08-14 отдаёт 404.

Сайт для сетевого варианта указывает порты **TCP 18181, 18182, 3306**. Установленный клиент к хранилищу ходит на **cmd 21600 / data 21601** (`storage_settings.ini`). Встроенный MySQL — локальные схемы `adeptsmetdb` / `adeptdatadb`. Это **не** открытый API и **не** канал интеграции.

Веб-экосистема Adept (ИД / стройконтроль, adeptw.ru) — другое изделие (Nginx, Laravel, PostgreSQL, React). К десктопному AUS / модулю ПРОЕКТ не относится.

**Вывод для проекта:** собственного открытого «формата Адепт для ПИР» нет. Конвертер обязан иметь **свой канон JSON (PIR-IR)**. Выгрузка в CXA / штатный импорт Адепт — отдельный этап после получения спецификации у вендора или эталонного файла из демоверсии.

### 4.2. Внутренний формат Адепт: `.cxa`

По статье ГК Адепт «Из каких программных комплексов можно конвертировать сметы в Адепт» (про линейку Адепт:Смета / Управление строительством, 2019):

- **Загрузить / сохранить `.cxa`** — внутренний формат обмена: папки, стройки, сметы, акты, планы.
- Файл может быть с паролем.
- Спецификация, XSD, JSON Schema **не опубликованы**.
- Тот же диалог умеет: Арос `.mdb`, Гранд `.xml`, АРПС `.arp` / `.ar2`, Allplan `.xca`, АВС-4 `.abc`, архив РИК `.zip`.
- Excel: создать пустую смету → «Расценка → Загрузить из Excel» → сопоставить номера столбцов. Это **плоский импорт строк СМР**, не формулы НЗ 707/пр.

Справка `AUS_HELP.PDF` (модуль СМЕТА, стр. 332–336) подтверждает тот же список **для клиента AUS**. Отдельного пункта «импорт сметы ПИР из Excel» в модуле ПРОЕКТ нет: импорт в главе 23 модуля ПРОЕКТ — это **задачи календарного плана из дерева объектов**, не Excel.

Рабочая гипотеза: `.cxa` общий по линейке (папки, объекты, сметы СМР и ПИР, акты, планы). Схема файла не опубликована.

**Запрет:** не реверс-инжинирить бинарный CXA и не писать в MySQL Адепт. Эталон `.cxa` снимать штатным «Сохранить в файл» из установленного AUS.

### 4.3. XML Минстроя (https://minstroyrf.gov.ru/tim/xml-skhemy/)

Действующие схемы этапа изысканий и проектирования (реестр от 09.06.2025):

- Пояснительная записка к ПД (v1.05)
- Ведомость объёмов работ
- Конъюнктурный анализ, сводка затрат
- Объектный сметный расчёт
- Сводный сметный расчёт
- Локальный сметный расчёт БИМ / РИМ
- Задание на проектирование (обязательно с 09.07.2025)
- Заключение экспертизы

Эти ЛСР/ОСР/ССР — методика **421/пр (СМР)**. Формы **2П / 3П / 4П / 1ПС** в реестре как отдельные XSD **не опубликованы**. По приказу Минстроя **783/пр п.3**, если схемы нет — документ на экспертизу допускается в **xls/xlsx/ods**.

Адепт пишет, что в комплексе «закладывается» выгрузка **задания на проектирование** в XML Минстроя. Это соседняя задача, не конвертация сметы ПИР.

В AUS тот же XML экспертизы сохраняется как **`.gge`** (смета, КА, ВОР). Импорт `.gge` — только сметы РИМ схемы v3_01. Для форм 2П/3П/1ПС этого канала нет.

### 4.4. API / SDK / интеграторы

Найдено:

- Публичного API/SDK «Адепт:Проект» / AUS нет (сайт, справка 1378 стр., GitHub).
- `aus_interbridge.exe` — мост **3D/IFC/Autodesk** (классы `InterBridgeConnector`), не HTTP API смет.
- Кастомные интеграции — коммерческие (модуль «Контроллер» ФКР и т.п.).
- Веб-Адепт (ИД) интегрируется с ИСУП через XML Минстроя / шину, не через SDK ПИР.
- Adeptik APS и язык Adept на GitHub — **другие продукты**, не ГК Адепт.

Действие: письмо в ГК Адепт (интеграция Excel ПИР → модуль ПРОЕКТ / CXA); эталон можно снять локально из AUS.

### 5.3. Три шаблона внутри одной книги

Конвертер не может быть «одним маппингом столбцов». В пилоте минимум три диалекта:

**A. Форма 2П по 707/пр (листы 1.1–1.4)**  
Колонки: № пп | наименование вида работ | обоснование МНЗ/НЗ (приказ, таблица, пункт, A, B, Xзад, количество) | расчёт стоимости (формула текстом) | стоимость, руб.

Пример позиции 1.1:

```
НЗ №849/пр … табл. 3.8 п.10  A=31.1 тыс.руб; B=122.993; Xзад=5 га; Кол=1
Полный комплекс (100%): (A + B * Xзад) * Кол * Ктек * Кст
(31 100 + 122 993 * 5) * 1 * 1.53 * 0.6
```

Встречаются: экстраполяция за диапазон (Xмин/Xмакс), К'пон по п.131(3) 707/пр, Ктек, Кст (стадийность РД 0.6).

**B. «Карточка АСУТП» (листы 1.5–1.8)**  
Не классическая 7-графка 2П. Параметры системы (число операций и т.п.), расчёт по СБЦ АСУТП 2016. Нужен отдельный парсер.

**C. Классическая форма 2П по СБЦ (листы 1.9–1.12)**  
Обоснование: сборник, таблица, пункт; коэффициенты из текста СБЦ (К3, К4…); на 1.11 — ведомственный коэффициент оптимизации Газпром и районный (письмо 9-10-17/40).

### 5.4. Что это значит для Адепт

Чтобы смета «жила» в Адепт:Проект, а не была мёртвой таблицей:

1. Каждую позицию привязать к записи справочника Адепт (НЗ 849/пр табл. 3.8 п.10 и т.д.).
2. Передать натуральный показатель X, стадию (РД), долю комплекса, коэффициенты.
3. Дать Адепт пересчитать; сравнить с Excel (допуск, например 1 ₽ или 0.01 %).
4. Свод 1ПС либо собрать в Адепт как ведомственную 1ПС (если лицензия/модуль Газпром–Роснефть), либо как свод 431/пр с ручной пометкой расхождения формы.

Риск: без отраслевого модуля Адепт коэффициент «оптимизации Газпром» придётся заводить вручную.

    "form": "1PS",
    "rows": [

## 8. Стратегия попадания в Адепт (по приоритету)

Пока CXA закрыт, идём ступенями. Каждая ступень уже полезна.

| Ступень | Что получаем | Зависимость |
|---|---|---|
| **S0** Канон PIR-IR + UI | Разбор Excel, проверка итогов, JSON | нет |
| **S1** Протокол маппинга | Словарь «текст обоснования → код НЗ/СБЦ» + форма AUS (`P707pr` / АСУТП / 1ПС) | эксперт + установленный AUS |
| **S2** Сверка печати | Сравнить колонки Excel с XSL 2П-707 / АСУТП / 1ПС | `templates_pir` |
| **S3** Эталон CXA | Вручную 2–3 позиции пилота в AUS → «Сохранить в файл» `.cxa` | `adept_us.exe` |
| **S4** Штатный импорт / CXA | Если вендор даст спецификацию или подтвердит канал | ответ ГК Адепт |
| **S5** XML Минстроя 2П | Только если появится XSD | Минстрой |

До S4 приложение — **подготовка и контроль** сметы к полуавтоматическому вводу в AUS, а не «один клик → готовый .cxa». Это нужно явно показать в UI.

Параллельно: в установленном AUS набить ГП (НЗ 849), одну карточку АСУТП и ЭХЗ, выгрузить `.cxa` / печать — эталон адаптера. В MySQL Адепт **не писать**.

| Риск | Влияние | Что делать |
|---|---|---|
| CXA закрыт, API нет | Нельзя обещать «файл для Адепт» в MVP | MVP = PIR-IR + сверка; адаптер — этап 5 |

## 13. Решение «что делать завтра»

1. Каркас Host + WebView2 + React по раскладке §22 (объект / бланк / инспектор), не 4 квадранта Адепт.
2. Парсер свода 1ПС и листа 1.1 (2П-707) до PIR-IR.

4. Не генерировать `.gge`/ЛСР Минстроя и не писать в MySQL Адепт.
5. Не строить MVP на OLE/кликах по Адепт (§18). FlaUI-спайк окна «Добавление расценки» — только если вендор не даст CXA.
6. Парсер Гранд **проектной** сметы (`.xml` / `.gsfx` → PIR-IR) и **запись** голого XML Гранда без штампа (§21).
7. Движок расчёта 2П (A+B·X, экстраполяция, Кпон, Ки1, РПД) + очередь уточнений.
8. Свод 1ПС в PIR-IR; в Гранд — папка из N файлов `sdtProjectSmeta` (отдельного XML свода ПИР в курсе Гранда нет).
9. Покупка «Адепт: Смета» не на пути ПИР. Справочники модуля **Проект** — образец UI коэффициентов/РПД, не API записи.

## 17. Печатная XML-модель `/smeta` (из XSL)

Печать ПИР: внутренний XML → XSLT → HTML. Это **не** заявленный формат импорта, но даёт словарь полей для PIR-IR.

Корень `/smeta`, атрибуты (частотные): `AdeptVersion`, `Numer`, `Contract`, `NumberTZ`, `customer`, `OurOrganisation`, `corporationName`, `Stady`, `QuarterLevel`, `Itogo`, `Vsego`, `VsegoNDS`, `NdsDec`, `ParentElementTag`, `xMultiplier`, `namesColumn`, `ObjectNameFromSvodn`, `SmetHeaderName`.

Строки: `smeta/row` с `@rascHeader`, `@subRasc`, `@font`, `@colspan`; ячейки `column1`…`column6`, `columnUnit`, `columnCount` (`@description`).

Свод 1ПС (`Sstylesheet.xsl`): колонки «№ пп», «Перечень выполняемых работ», «Характеристика…», «Ссылка на № смет по формам 2П, 3П», подколонки изыскательских / ПД / РД / … — совпадает с листом «СВОД» пилота.

АСУТП (`Asutp1stylesheet.xsl`): «Приложение к Смете №…»; данные ещё из `/data/db[@name='smetdb']/table/record/osnov` — карточка параметров, как листы 1.5–1.8.

PIR-IR должен покрывать эти атрибуты, чтобы потом заполнять AUS (вручную или через будущий CXA), а не копировать только сумму.

|---|---|
| Сгенерировать XML и штатно импортировать как смету **2П/1ПС** | **Нет такого импорта.** XML в меню — СМР (Гранд, Минстрой `.gge`, Беларусь) или печать |
| Встроить `adept_us` в наше приложение как OLE/ActiveX (`Excel.Application`-стиль) | **Нельзя.** В HKCR нет ProgID/CLSID Адепт. В exe нет `QAxServer` / `RegisterActiveObject`. Адепт — **клиент** Excel/Word, не сервер |
| Надстройка «как VSTO для Excel» | **Нет SDK.** Единственные плагины — Qt `IConverter` для **АВС-4 СМР** |
| Клики/клавиатура по уже открытому Адепт (UIA / FlaUI) | **Технически возможно, как продукт — нет.** Qt 5 отдаёт UI Automation; горячие клавиши ПИР есть. Хрупко, лицензия, фокус, версии UI |

Рабочий канал обмена ПИР по-прежнему **`.cxa`** (без опубликованной схемы) + свой PIR-IR. Автозаполнение экрана — запасной лабораторный путь, не архитектура MVP.

### 18.2. Какие XML Адепт вообще ест

Фильтр открытия из бинарника: `*.dat; *.cxa; *.xml; *.arp; *.arps; *.ar2; *.abc; *.xca`. Рядом в коде — `ImportGrand`, `ImportMinstroy`, `ImportABC4`, `ImportArps*`, `ImportAros`, `ImportAllplan`, `ImportWinRik`, `ImportBelarusXml`, `ImportIFC`, `ImportFromExcel`, `ImportAdept` / `ImportAdeptOld`.

Это **не** формы 2П:

| XML | Модуль в exe | Что получится |
|---|---|---|
| Гранд `.xml` локальная СМР | `ImportGrand.cpp`, GUID `{2B0470FD-477C-4359-9F34-EEBE36B7D340}` | СМР; меню скрыто без модуля «Адепт: Смета» |
| Гранд `.xml`/`.gsfx` проектная смета | GUID `{39200715-3435-47E0-8C27-68A028AD6D25}` **в exe нет** | Адепт не импортирует |
| `.toaus` | «Адепт:Проект (*.toaus)» | Свой обмен модуля ПРОЕКТ, не Гранд; схема не опубликована |
| Минстрой `.gge` | `ImportMinstroy.cpp` | СМР РИМ 3.01 (421/пр) |
| Беларусь XML | `ImportBelarusXml.cpp` | СМР |
| `Excel file (*.xml)` | `ImportFromExcel.cpp` + COM Excel | SpreadsheetML / загрузка **расценок СМР** по столбцам |
| Печатный `/smeta` из XSL ПИР | только печать | Импортёра нет |
| Primavera XML, MS Project | `ExportXMLPrimavera.dll`, `exportMsXml` | **Экспорт** календарного плана, не ПИР |

Таблица `gges_pir` и принтеры `PirGgeXlsxPrinter` — расчёт **ГГЭ по смете ПИР**, не импорт Минстроевского `.gge` как 2П.

**Исключение, которое не помогает Excel:** `ImportAdeptOld` умеет процессоры `SmetType2PProcessor`, `SmetType2PIzyskProcessor`, `SmetType3P707prProcessor`, `SmetType3PRzdProcessor`, `SmetTypeMRRProcessor`, распаковку свода и GGE. Это импорт **старых пакетов самого Адепт**, не чужого XML. Спецификации нет; реверс запрещён (§4.2).

Следствие: выгрузить из конвертера «похожий XML» (Гранд / GGE / `/smeta`) и ждать смету 707/пр **нельзя**. Адепт либо отвергнет файл, либо создаст СМР.

### 18.3. OLE: кто кем управляет

В `adept_us.exe` есть `QAxObject` / `QAxWidget`, `Excel.Application`, `Word.Application`, `CLSIDFromProgID`, `GetActiveObject`, `CoCreateInstance`. Это Qt ActiveX **клиент**: Адепт сам открывает Excel/Word.

Зачем ему Excel (пути в бинарнике):

- `PirFormExcelPrinter.cpp` / `PirFormExcelThreadPrinter.cpp` — **печать форм ПИР в Excel** (в справке: 2П комплексная и др. только через редактор MS Excel);
- `ImportFromExcel.cpp`, `PostsExcelImporter.cpp`, `CalcImportFromExcel.cpp` — импорт сотрудников, расценок СМР, расчётов из книги;
- `PrintManager.cpp`, `ofe.cpp` — печать/свод в Excel.

Обратного канала нет: наше приложение **не** может сделать `CreateObject("Adept.Application")` и вызвать `OpenEstimate`. В реестре классов (`HKCR`) имён с `adept` / `AUS` **0**. `QAxServer` в exe нет. `ole32.dll` тянется из-за клиента Excel.

Путь «вставить Адепт Ole-объектом в форму SNTP-ADEPT, как документ Word» закрыт: это не in-proc OLE-сервер и не ActiveX-контрол.

### 18.4. Надстройки и точки расширения

| Слот | Что есть | Для ПИР Excel |
|---|---|---|
| `plugins\abc4RU\Converter.dll`, `abc4KZ\Converter.dll` | Qt-плагин `ABC4Converter`, IID `com.Converter.ConverterPlugin.IConverter/1.0`, грузится из `ImportABC4.cpp` | Только **АВС-4 СМР** (RU/KZ). Заголовков/SDK нет |
| `aus_interbridge.exe` | 3D/IFC (`IBimBridge`) | Нет |
| `IPirBridge` в exe | Внутренний C++-интерфейс модулей (рядом `ISmetTable`, `IKoeffsPir`…) | Не COM, не публичный API |
| `Qt5RemoteObjects.dll` | IPC внутри клиента / InterBridge | Не API смет |
| `Qt5Script.dll` | Движок Qt Script для UI/QML | Нет макроязыка сметы |
| `hotkeys.info` | Назначаемые клавиши | Рычаг для UIA, не API |
| `templates\templates_pir\*.xsl` | Печать | Не импорт |
| COM add-in / `.tlb` / `.ocx` | Не найдены | — |

Свой `Converter.dll` с тем же IID теоретически подхватится как ещё один СМР-конвертер. Это не путь ПИР и без ABI вендора это реверс плагина — вне скоупа.

CLI `--console` / `--triggers` в строках exe — флаги **встроенного MySQL**, не командная строка Адепт.

### 18.5. Управление экранной формой (не OLE)

Клиент — Qt Widgets + QML. Платформенный плагин `platforms\qwindows.dll` содержит полный стек **Windows UI Automation** (`QWindowsUiaMainProvider`, `ValueProvider`, `InvokeProvider`, `GridProvider`, …). Inspect / FlaUI / WinAppDriver **могут** увидеть кнопки и поля, у которых Qt выставил accessible-имя (часто текст кнопки / `windowTitle` диалога).

Это **не** встраивание Ole-объекта. Это внешняя автоматизация чужого GUI, как Selenium для окна.

Экранный сценарий «как сметчик» (справка стр. 950–955, 1029–1031):

1. Открыть/создать смету 2П 707/пр в модуле ПРОЕКТ.
2. В СНБ найти расценку (код НЗ) → перенести в смету (мышь или кнопка БД).
3. Диалог **«Добавление расценки»**: Х зад (или Мощность), формула A+B·X / экстраполяция / Кпон, Ктек, Кст. Для групповых — блок «Параметры расценки».
4. Коэффициенты: кнопка «Коэффициенты выбранной расценки» или **Ctrl+R**.
5. Раздел / текстовая строка / свободная строка: **Ctrl+U**, **Ctrl+T**; «Создание строки» — характеристика, обоснование, формула, стоимость (это **не** привязка к СНБ).

Горячие клавиши `[Смета ПИР]` (`hotkeys.info`):

| Клавиша | Действие |
|---|---|
| Ctrl+N | Копия расценки |
| Ctrl+E | Редактировать расценку / работу / раздел |
| Ctrl+U | Создать раздел |
| Ctrl+T | Текстовая строка |
| Ctrl+R | Коэффициенты выбранных |
| Ctrl+W | Создать работу |
| Ctrl+F | Поиск по базе СМР/ПИР |
| Ctrl+C / Ctrl+V | Буфер (общие) |

Если автоматизировать, то **только путь через СНБ** (поиск кода → диалог Х зад). Свободная «Создание строки» с формулой текстом **не** даёт пересчёт от нормативной базы — это обход модели, которую должен переносить конвертер.

Ограничения UIA:

- Нет гарантии, что все QLineEdit в «Добавление расценки» имеют устойчивые AutomationId (у Qt чаще имя = видимый текст, он плывёт с локалью/версией).
- Модальные диалоги, предупреждение экстраполяции (Х зад < Х мин/2), групповые расценки, АСУТП-карточка — разные деревья.
- Нужен запущенный сеанс с лицензией, фокус окна, запрет ручного ввода параллельно.
- Любой релиз AUS ломает скрипт.
- Юридически это управление чужим UI, не интеграционный API.

Практичный стек спайка (если когда-нибудь понадобится): FlaUI 3 + UIA3, окно по заголовку Адепт, диалог по `Name = «Добавление расценки»`, поля через `ValuePattern`, кнопки `Invoke`. Запас: SendInput по Tab-порядку + `hotkeys.info`. Не: DLL-injection / `QMetaObject` из чужого процесса.

### 18.6. Что это значит для SNTP-ADEPT

1. **Штатный импорт XML в Адепт как замена CXA для ПИР — закрыт** (в т.ч. Гранд проектная смета, §19). XML в продукте: вход Гранд → PIR-IR, свой канон, отчёты.
2. **OLE-хост Адепт — закрыт.** Excel COM оставляем разве что для чтения кривых книг (не основной путь; в стеке ClosedXML).
3. **Надстройка в `plugins\` — только АВС-4 СМР**, не писать свой Converter.dll.
4. **Съём «Базы ПИР» — отдельная утилита, не обмен.** `tools/Sntp.Adept.Harvest` читает уже открытое окно Адепт (FlaUI). Кнопку «Добавить» не нажимает, в MySQL Адепт не пишет. Канон шифра — `BasisParser`, рабочая папка — `project.json` (`desktop.ini` только подпись), `.gge` отклоняется, ФГИС ЦС — реестр без A/B.
5. Если вендор не даст CXA, лабораторный робот «найти код в СНБ → заполнить Х зад → Ctrl+R» может набить пилот **после** того, как Inspect.exe покажет стабильное дерево диалога. Это не замена формата обмена.

## 19. Почему в этой лицензии нет импорта Гранд XML/GSFX (ПИР)

Образцы: `MD/Проектная смета.xml`, `MD/Проектная смета.gsfx` (Гранд-Смета **16.2.1.59411**, 14.08.2026). Окно «О программе»: **Адепт 2026.4.1.15**, лицензия до 30.06.2027, подключены только **Адепт: СЭД** и **Адепт: Проект**.

Это не «в 2026.4 вырезали импорт». Импорт Гранда **есть в этом же exe**, но это другой документ и другой модуль.

### 19.1. Две независимые причины, почему пункта в UI нет / файл не подойдёт

**А. Лицензия.** Каталог модулей в `adept_us.exe`: «Адепт: Смета», «Адепт: Управление строительством», «Адепт: СЭД», «Адепт: Проект», «Адепт: BIM», НЦС-НЦКР, РЖД, ГПП, перебазировка, шифрование ССЦ, удалённый рабочий стол. У этой копии в «Подключенные модули» только СЭД + Проект. Диалог **«Импорт из Гранда»** с фильтром `Смета ГРАНД (*.xml);;Любой файл (*.*)` живёт в контуре **модуля Смета** (`ImportGrand.cpp` / `Proc_Smet.cpp`: НР/СП, ФОТ, TSN, разборка, ЗПМ — математика **ЛСР СМР**). Модуль ПРОЕКТ для обмена своими файлами показывает **`Адепт:Проект (*.toaus)`**, не Гранд. Докупить «Адепт: Смета» покажет импорт Гранда, но см. пункт Б.

**Б. Тип документа Гранда.** Адепт знает **один** GUID Гранда: `{2B0470FD-477C-4359-9F34-EEBE36B7D340}` (рядом `Generator` = `GrandSmeta` / `Estimo.Connect` / `QuickSmeta`). Образец ПИР:

| Поле | Образец | В Адепт |
|---|---|---|
| `DocumentType` | `{39200715-3435-47E0-8C27-68A028AD6D25}` | **нет в exe** |
| GSFX `DocType` | `sdtProjectSmeta` | **нет в exe** |
| `ProjectPhase` | `ProjectDoc` | **нет в exe** |
| `RelativeFactors` | состав ПД/РД (РПД) | **нет в exe** |
| расширение `.gsfx` | zip | **нет строки `gsfx`/`GSFX`** |

Даже с модулем Смета этот файл либо отвергнется, либо (если открыть «любой файл») разберётся парсером **локальной СМР** и не станет сметой 2П.

`.gsfx` = zip: `Properties.txt` + `Data.xml` (тот же XML + `GrandSmetaSign`) + `Data.sign`. Адепт zip Гранда не распаковывает.

### 19.2. Что на самом деле лежит в XML Гранда (это ПИР, не СМР)

Корень `<Document Generator="GrandSmeta" RegionName="Проектно-изыскательские работы" RoundMode="Round10">`. Две позиции СБЦП, стадия П (`ProjectPhase=ProjectDoc`), итог GSFX `Total=901110` (базис 2001).

Позиция 1: код `СБЦП19-5-1`, `PriceA=8640`, `PriceB=17`, `Quantity/@Fx=1000` (Х зад), в `<Items>` интервал 20–60 → экстраполяция `Formula="(A+B*(0.4*X2+0.6*X))*К1*Ки1"`, `ExpandedFormula="(8,64+0,017*(0.4*60+0.6*1000))*0,9*0,4"`, `Total=6930`. `Ки1` — стадийность (П=0,4 / Р=0,6 / РП=1). `К1=0,9` — РЖД 2697р. Блок `RelativeFactor` — доли РПД (ПЗ, конструктив, ПОС, смета…).

Это та же модель, что Адепт считает в 2П и что должен хранить PIR-IR. Гранд XML ПИР — **хороший второй вход** конвертера (часто чище Excel). Это не формат, который Адепт проглотит.

### 19.3. Схема, которую имеет смысл развивать у нас

Не «подделать GUID 2B0470FD и залить как СМР». Развивать разбор **проектной** сметы Гранда → PIR-IR:

```
GSFX → unzip Data.xml
XML  → Document / Chapters / Chapter / Position
         Code, Caption, Units, ESNTable, PriceA, PriceB
         Quantity/@Fx (Xзад), Items/Item Min/Max (Xмин/Xмакс)
         Formula, ExpandedFormula, Total, PriceLevel
         Factors/Factor (Ки1, К1… по стадиям ProjectDoc/WorkDoc/WorkProject)
         RelativeFactors/RelativeFactor (РПД %)
       Document/@ProjectPhase, Region*, RoundMode
       RZDCalcOptions (если есть)
```

Кодировка файлов: `windows-1251`. GSFX `Crypted=False` на образце; при `Crypted=True` без ключа Гранда не читать.

Выход по-прежнему PIR-IR, затем CXA / `.toaus` / вендор. Генерировать Гранд-СМР XML ради импорта в Адепт **нельзя**: получится ЛСР, не 2П.

### 19.4. Свой файл модуля ПРОЕКТ

В exe: «Импорт файлов из Адепт: Проект», фильтр `*.toaus`, ремарка «Импорт реализован для версий не старше 2025.1». Это обмен **Адепт↔Адепт**, не Гранд. Спецификации `.toaus` нет; не реверсить. Для эталона снять штатным сохранением, как `.cxa`.

## 20. Решение: Смета куплена + XML `GrandSmetaSign` — каким вариантом идти

Допущение: модуль **Адепт: Смета** будет куплен. Вопрос: тащить ли ПИР в Адепт через XML Гранда (в т.ч. с `GrandSmetaSign`), или нет.

### 20.1. Две разные «подписи» в файле Гранда

| Что | Где в образце | Смысл | Адепт 2026.4.1.15 |
|---|---|---|---|
| `<GsDocSignatures>` | и `.xml`, и `.gsfx` | ФИО/должности для печати (ГИП, составил, проверил). Не криптография | Импортёр СМР **знает** тег (`GsDocSignatures` в exe рядом с `IMPORT-GRAND`) |
| `Document/@GrandSmetaSign` | **только** `Data.xml` внутри `.gsfx` (189 Base64 → 141 байт) | Штамп целостности пакета Гранда | Строки **`GrandSmetaSign` в exe нет** — Адепт **не читает и не проверяет** |
| `Data.sign` | только `.gsfx`, 128 байт: `u32le` длина + 100 символов названия организации + 24 байта MAC | Подпись zip-пакета | В exe нет |
| `Properties.txt` `SignType=0`, `Crypted=False` | `.gsfx` | Пакет не шифрован, тип подписи «простой» | Адепт `.gsfx` не открывает |

Итог по штампу: **`GrandSmetaSign` — внутренность Гранда, не протокол Адепта.** Голый `Проектная смета.xml` (Save as XML) штампа **не содержит** и при этом является штатным обменом Гранда. Наш парсер штамп пропускает. Генерировать его мы **не можем** (нет ключа Гранда) и **не должны** — это не вход в Адепт.

### 20.2. Четыре варианта после покупки Сметы

**Вариант A — «открыть этот XML в Адепт: Смета как есть».**  
Меню «Загрузить смету из Гранд (*.xml)» появится (статья ГК Адепт, 2019: то же меню, затем «Привязать к базе»). Парсер ждёт `DocumentType={2B0470FD-477C-4359-9F34-EEBE36B7D340}` и математику ЛСР (`Proc_Smet`: НР/СП, ФОТ, TSN). Образец — `{39200715-…}` / `sdtProjectSmeta`. Штамп не поможет: его Адепт не смотрит. **Отказ или каша СМР. Для ПИР закрыт.**

**Вариант B — «переклеить GUID на 2B0470FD, при желании скопировать/подделать GrandSmetaSign, скормить как ЛСР».**  
Позиции СБЦП с A+B·X и РПД станут строками строительной сметы. Адепт:Проект эту смету как 2П не пересчитает. Подделка штампа ни к чему (Адепт его нет) и юридически лишняя. **Запрещён.**

**Вариант C — «наш конвертер пишет XML/GSFX Гранда с GrandSmetaSign, чтобы Адепт или Гранд приняли».**  
Адепт ПИР-GUID не импортирует. Валидный `GrandSmetaSign` без Гранда не выпустить. Голый XML без штампа Гранд открывает сам — это канал **к коллегам в Гранде**, не в Адепт. Как выход в Адепт — **нет**. Как поздний экспорт «Excel → XML для Гранда» — опция, не MVP.

**Вариант D (принятый) — Гранд XML/GSFX только как вход в PIR-IR; в Адепт ПИР — модуль Проект (`.cxa` / `.toaus` / вендор).**  
Покупка Сметы **не на критическом пути ПИР**. Она нужна, если параллельно надо принимать **локальные СМР** Гранда (другие отделы, стройка). Для Степновской / 2П:

```
Excel 2П/1ПС  ─┐
               ├─► PIR-IR (свой JSON) ─► сверка итогов ─► Адепт:Проект (.cxa / .toaus / спецификация)
Гранд .xml/.gsfx┘         ▲
                    GrandSmetaSign снять и забыть
```

Маппинг входа Гранда уже ясен по образцу (§19.3): `Code`, `PriceA/B`, `Quantity/@Fx`, `Items` min/max, `Formula`, факторы стадий (`Ки1` П/Р/РП), `RelativeFactor` = РПД, `ProjectPhase`.

### 20.3. Что даёт покупка Сметы (честно)

| Даёт | Не даёт |
|---|---|
| Пункт «Гранд (*.xml)» и импорт **ЛСР СМР** GUID `{2B0470FD-…}` | Импорт проектной сметы `{39200715-…}` |
| Выгрузка **СМР** Адепта обратно в XML Гранда (блог ГК Адепт) | Выгрузку сметы 2П в XML Гранда ПИР |
| После импорта СМР — «Привязать к базе» ГЭСН/ФЕР | Привязку СБЦП в модуле Проект через этот диалог |
| Контрольный опыт: СМР-файл Гранда проходит, ПИР-файл — нет | Обход закрытого CXA |

Первый опыт после покупки (не разработка): импортировать **заведомую локальную СМР** Гранда; затем `MD/Проектная смета.xml` — сохранить текст ошибки. Это подтвердит GUID, не «баг штампа».

### 20.4. Решение одной строкой

**В Адепт ПИР по-прежнему не через XML Гранда** (вариант D для *импорта в Адепт*). **В Гранд ПИР — да: читать и писать голый XML** без `GrandSmetaSign` (это и есть бывший вариант C, но как выход к коллегам в Гранде, не в Адепт). Смета — опциональный модуль для СМР. Рабочий продукт: §21.

## 21. Контур продукта: Excel + XML Гранда → редактор ПИР → XML Гранда

Цель этого варианта: наше приложение — рабочее место сметчика ПИР (WebView2), которое **понимает ту же модель, что Гранд «проектная смета» и Адепт:Проект**, принимает Excel Степновской и XML Гранда, даёт уточнить расчёт, завести доп. сметы и свод, сохранить XML, который Гранд открывает через «Файл → открыть / импорт XML». В Адепт этот XML по-прежнему не грузится (§19–20); Адепт здесь — **эталон справочников и UI коэффициентов**, не приёмник файла.

### 21.1. Справочники и экран Адепт:Проект (AUS_HELP, модуль ПРОЕКТ)

Меню **«Справочники ПИР»** (стр. 899–900): индексы; коэффициенты; типовые разбивки РПД; виды деятельности; сокращения; РПД для группировки.

**Справочник «Коэффициенты»** (стр. 919–920), таблицы `adeptdatadb.koeffs_pir` / `koeffs_pir_formulas` / `my_koeffs_pir`:

- Начисление на расценку, на **РПД**, на состав сооружений, на начисления сметы.
- Нормативные разделы не править; свои — в «Сборник моих коэффициентов» (+ СУР, начисления).
- Поля: `name`, `type`, `value`, `formula_id`, `has_range`, `min_value`, `max_value`, флаг `BIM`.
- Формулы: `formula`, аргументы X/P (`unit_x`, `range_arg_x`, `name_arg_x`…).

Окно **«Коэффициенты расценки»** (стр. 1028, 1038–1039), кнопка как Ctrl+R:

- Чекбокс выбора; наименование; обоснование; значение; **тип**; мин/макс (справочные); количество (кратность).
- Типы сочетания (важно для движка, в XML Гранда этого нет — там только множители в формуле):
  - **Ценообразующий** — значения перемножаются;
  - **Усложняющий** — дробные части складываются с 1;
  - **Составной** — складываются.
- Начислить: выбранные / все расценки сметы; новый коэф. только на текущую строку, в справочник — если нужен везде.

РПД / состав (стр. 1036–1037): вернуть базовые Кст и РПД из СНБ; показать/скрыть РПД и состав сооружений; «учитывать / не учитывать / не учитывать, но печатать».

Свод (стр. 1115): **Общее → Создать сводную смету на ПИР** на объекте (договор/смета). Таблица `svodnsmets_pir`.

Индексы: `indexes_pir` / `my_indexes_pir`; индексы СМР в справочнике ПИР нужны для расчёта «от стоимости строительства» (как % в СБЦП энергетика).

Шаблон сметы (стр. 910): Кст АСУТП отдельными полями; 2П «Всего» = формула×Кст(ПД+РД) vs сумма стадий; лимит корректирующих МРР ≤ 2.0.

**АСУТП 2016 и 3П МДС (реализовано в парсере/движке, 2026-08-15):** баллы и части — HELP стр. 991–993; редактор 3П — стр. 1087–1090. Карта Excel V3.2 и PIR-IR — `02_REVISION.MD` §1.4–1.6. UI: сворачиваемая `aside.left`, % локальной от свода 1ПС без НДС — §9 там же.

**Запрет:** не писать в MySQL Адепт. Справочник для матчера — **снимок только чтение** (экспорт имён/типов), либо ручной CSV. `.apr` в `catalogs\` закрытый.

### 21.2. Экран Гранда: составление проектной сметы

Источники: help.grandsmeta.ru гл. 26; курс `smety-na-pir.pdf`; макрос `Document.DocType = 9` (`dtProjectSmeta` = `sdtProjectSmeta`).

| Шаг UI Гранда | Что делает | Наш экран |
|---|---|---|
| Файл → регион «Проектно-изыскательские работы» | База СБЦП/НЗ | Справочник кодов (позже); пилот — код из Excel/XML |
| Создать → **Проектная смета** | Документ не ЛСР | Новая смета `form=2P` |

| База / Вставить в смету / DnD | Групповая расценка: все A,B,Xmin,Xmax | `Items/Item` в XML |
| Количество = X зад | Автовыбор строки группы + формула | Поле X; движок |
| F3 / Доп. информация → Стоимости | Таблица интервалов | Редактор группы |

| Печать 2П | Часть колонок скрыта | Позже XSL/HTML |

Формулы (те же, что Адепт 707/пр и пилот Excel):

- В диапазоне: `С = (A + B·X) · ∏Ki`
- X < Xmin: `A + B·(0,4·Xmin + 0,6·Xзад)`
- X > Xmax: `A + B·(0,4·Xmax + 0,6·Xзад)`
- X < 0,5·Xmin или X > 2·Xmax: без опций — **ошибка** (красный); с опциями — экстраполяция «больших» или `С = [A+B·(0,4·Xmin+0,6·0,5·Xmin)]·Кпониж`, Кпон = X/0,5Xmin или 0,7–0,9 экспертно.

% от стоимости строительства (СБЦП энергетика): интерполяция по таблице + коэф. `ОБЪЕМ*1e6/100`.

В курсе Гранда **нет** отдельного документа «сводная смета ПИР». Свод 1ПС — наша сущность + папка из нескольких XML. В Адепт свод — отдельный тип.

### 21.3. Формат XML Гранда для стоимости ПИР (по образцу + пустые узлы)

Эталон: `MD/Проектная смета.xml` (Гранд 16.2.1, `windows-1251`). GSFX = zip тех же данных + штамп; **пишем `.xml`**, не `.gsfx`.

Корень:

```
Document
  @ProgramVersion @Generator="GrandSmeta"
  @DocumentType="{39200715-3435-47E0-8C27-68A028AD6D25}"
  @ProjectPhase="ProjectDoc"|"WorkDoc"|"WorkProject"   ← П / РД / РП
  @RegionCode @RegionName="Проектно-изыскательские работы"
  @ZoneName @RoundMode @ItogExpandTo @MaxSysID
  IdsGenerator @InternalCounter
  GsDocSignatures / Item (@Caption @ID) [Attributes]
  Parameters                         ← пусто в образце; стадия уже в @ProjectPhase
  VidRab_Catalog / Vids_Rab / VidRab_Group / Vid_Rab (@ID @OsColumn)
  AddZatrats                         ← лимитированные; для 2П обычно пусто
  Factors / Factor                   ← Ки1 к итогам: @Identifier @ProjectDoc @WorkDoc @WorkProject @Level @Options
  Indexes                            ← Ктек; пусто в образце
  Chapters / Chapter / Position
  RelativeFactorsSummary / Item      ← итог распределения РПД по смете
  OsInfo (@OSChapter @LinkType) / CCChapter
  RZDCalcOptions                     ← отраслевое; не обязательно
```

Позиция (ядро стоимости):

| XML | Смысл | Excel пилота |
|---|---|---|
| `@Code` `СБЦП19-5-1` | обоснование | НЗ/СБЦ табл.п. |
| `@Caption` `@Units` `@ESNTable` | имя, ед., ссылка на табл. | кол. 2–3 |
| `@PriceA` `@PriceB` | A, B (в XML часто рубли; в ExpandedFormula — тыс.) | A, B |
| `@Formula` `@ExpandedFormula` | символьная / числовая | кол. «расчёт» |
| `@Total` `@PriceLevel` | итог позиции, уровень (2001) | стоимость |
| `Quantity/@Fx` | X зад | Xзад / кол-во |
| `Items/Item` `@MinQuantity` `@MaxQuantity` `@PriceA/B` `@Code` | группа интервалов | Xмин/Xмакс |
| `Factors/Factor` `@Identifier` `@Code` три стадии | К1, Кпон… | Ктек, Кст, Газпром |
| `RelativeFactors/RelativeFactor` `@ProjectDoc` `@WorkDoc` `@RelativePrice` | РПД % и ₽ | редко в Excel явно |
| `@Vr` | вид работ каталога | — |
| `@HasDBFactors` | коэф. из базы | — |

Идентификаторы в `@Formula` (`Ки1`, `К1`) **обязаны** совпадать с `Factor/@Identifier`. Стадия документа выбирает, какое из трёх чисел подставить.

Читать: `.xml` как есть; `.gsfx` → `Data.xml`, атрибут `GrandSmetaSign` выбросить. Писать: тот же набор узлов, `Generator="GrandSmeta"`, GUID проектной сметы, **без** `GrandSmetaSign`. Критерий: Гранд 16 открывает файл и пересчитывает близко к нашему `Total` (допуск как у Excel).

Не писать GUID `{2B0470FD-…}` (ЛСР). Не выпускать GSFX со своим штампом.

Провалы схемы (нужны ещё образцы из Гранда): смета изысканий; форма 3П/4П; свод 1ПС/431; карточка АСУТП; заполненные `Indexes` и `AddZatrats`; `Crypted=True`.

### 21.4. Как сделать продукт (экраны и поток)

```
Excel (3 диалекта) ─┐
Гранд .xml/.gsfx   ─┼─► PIR-IR ─► очередь уточнений ─► редактор
Новая смета / свод ─┘         │
                              ├─ движок 2П (формулы §21.2)
                              ├─ справочник коэф. (снимок Адепт + свои)
                              └─ экспорт: N× XML Гранда + свод 1ПС (наш JSON/xlsx)
```

1. **Импорт XLS** — листы 1.1–1.12 и СВОД (§5): шапка, позиции, формула текстом, Ктек/Кст/Кпон, три диалекта (707, АСУТП, СБЦ). Итоги Excel — контроль.
2. **Импорт XML** — разбор §21.3; слияние в тот же PIR-IR (объект = папка смет).
3. **Уточнения** (как красные строки Гранда): нет X; X вне 0,5Xmin…2Xmax без политики; код не сопоставлен; тип коэф. Адепт vs множитель Гранда; нет Ки1; РПД сумма ≠ 100; Ктек не задан; АСУТП без карточки; расхождение пересчёта и Excel > допуска.
4. **Создать смету** — пустой `2P` с Ки1 0,4/0,6/1, стадия с объекта, раздел по умолчанию.
5. **Свод** — как Адепт «создать сводную на ПИР»: строки = локальные сметы, форма 1ПС пилота; НДС; в Гранд уходит **набор XML**, не один «сводный GUID» (его нет в курсе).
6. **Редактор** — разделы (`Chapter`), позиции, X, группа `Items`, факторы (три стадии + идентификатор), РПД вкл/выкл, индексы, учитывать/не учитывать.
7. **Сохранение XML** — по одной смете или пакет в папку; cp1251; round-trip через Гранд.

Движок обязан воспроизвести `ExpandedFormula` образца (экстраполяция 1000 при Xmax=60, Ки1=0,4, К1=0,9 → 6930).

Типы Адепт (ценообразующий / усложняющий / составной) при экспорте в Гранд **сворачиваются в идентификаторы и числа в Formula** — иначе Гранд не поймёт. В PIR-IR хранить оба представления.

### 22.2. Каркас экрана: две школы

**Адепт:Проект** — «четыре квадранта» (справка стр. 898):

1. Слева сверху — дерево объектов / договоров / смет.  
2. Справа сверху — смета или карточка выбранного узла.  
3. Слева снизу — СНБ (сборники и тексты).  
4. Справа снизу — таблицы и расценки выбранного сборника.

Плюс: ставка и база всегда рядом; перенос в смету без смены «мира». Минус: для задачи «разобрать Excel и уточнить 12 смет» нижняя половина СНБ пустая и крадёт место; новичок не видит, где «главное». Команды размазаны: Общее / Справочники ПИР / панель сметы / ПКМ. Undo перечислен точечно (стр. 1032) — не все жесты.

**Гранд** — «бланк 2П + модалки»:

- Вкладка Объекты — список документов (проектная смета как тип).  
- Открытый документ — таблица, похожая на печать 2П, но детальнее (часть колонок на печать не идёт).  
- База — отдельная вкладка слева; два окна / DnD / буфер.  
- Модель расчёта спрятана: **F3** (стоимости, коэф. ТЧ/справочник, РПД), **F6** (стадия, Ки1, индексы, Кпон, округление).  
- Ошибка = красная строка + причина «формула не определена».  
- Печать: Файл → Формы → «Проектные работы».

Плюс: бланк читается как знакомая 2П; X в колонке Количество сразу пересчитывает группу. Минус: F3/F6 отрывают модель от строки; три значения П/РД/РП не видны, пока не откроешь параметры; свода ПИР как документа в курсе нет; типы коэффициентов Адепта (ценообразующий / усложняющий / составной) отсутствуют — только идентификатор в формуле.

| РПД | F3 / группировка слева; «не учитывать» зачёркивает | блок в строке, показать/скрыть, вернуть из СНБ, коэф. на РПД | раскрытие строки + инспектор; не удалять — выключать (как Гранд) |
| Ктек | F6 индексы, Кинф в формуле или в итоге | `indexes_pir`, показ Ктек≠1 | шапка объекта: квартал/Ктек; видно в формуле строки |
| Сменить стадию | F6, пересчёт всех Ki | стадия сметы; вставка из буфера берёт стадию **новой** сметы | шапка объекта; предупреждение «пересчитать все локальные» |
| Свод | нет в курсе ПИР | НДС 18/20, без НДС / НДС в концовке, пересчёт из локальных, этапы | мастер 1ПС: НДС 22% пилота; раскладка по стадии как Адепт; кнопка «обновить из локальных» |
| Ошибка | красный + текст причины | мало явной очереди; фильтр по меткам | **очередь уточнений** (как inbox), клик → строка |
| Excel | нет импорта 2П | нет импорта 2П | первый класс: превью листа + карта колонок |
| Печать vs экран | бланк богаче печати | десятки чекбоксов шаблона (стр. 902–904) | два режима: «работа» (всё) и «как 2П/1ПС» (как Excel) |
| Отмена | штатный Ctrl+Z документа | список жестов на стр. 1032 | полная история PIR-IR (команды), не урезанный список |

Взять у Гранда: живой пересчёт от X; группа интервалов в позиции; красный с причиной; «не учитывать» вместо удаления РПД; идентификаторы в формуле.

Взять у Адепт: типы коэффициентов; коэф. на РПД; свод с раскладкой по стадии и пересчётом из локальных; шаблон «что показывать в графе 2/4»; «не учитывать, но печатать»; дерево объекта.

Не брать: 4 квадранта как единственный layout; прятать модель в F3/F6; молчаливый импорт «цифр без модели»; выпуск CXA/подписанного GSFX.

### 22.4. Информационная архитектура SNTP-ADEPT

Один объект на экране (пилот Степновская). Не четыре равных панели.

```
┌ Шапка объекта: имя, стадия П/РД/РП, Ктек, округление, НДС, очередь уточнений (N)
├ Слева     список смет + свод 1ПС (суммы, статус импорта)
├ Центр     бланк 2П: №, имя, обоснование, формула, ₽
│            раскрытие строки → РПД / коэф. (как группировка Гранда, но в таблице)
└ Справа    инспектор выбранного: X, Items, Factors×3 стадии, тип Адепта, РПД вкл/выкл
Вкладки шапки: Сметы | Свод | Уточнения | Импорт (Excel/XML) | Экспорт
```

Команды (имена как у Адепт, чтобы сметчик не учил заново): создать раздел / строку / текст; коэф. выбранных; учитывать. Плюс наши: «сопоставить код», «пересчитать», «сверить с Excel».

Горячие клавиши: не конфликтовать с браузером WebView2 (Ctrl+T/W/N заняты Chrome). В хосте перехватить: Ctrl+E правка, Ctrl+R коэф., Delete, Ctrl+Z. Вкладка «смета+база» Адепта (F3 в AUS) нам не нужна на старте.

### 22.5. Принципы «продуманнее обеих»

1. **Модель на виду.** Формула и X не в модалке. Инспектор приколот справа, не F3.  
2. **Объект, не документ.** Свод и 12 локальных — одна сессия; Гранд мыслит файлами, Адепт — деревом, мы — комплектом пилота.  
3. **Уточнение как работа, не как ошибка отрисовки.** Inbox с причиной, полем и предложенным действием (задать X / включить Кпон / сопоставить СБЦП).  
4. **Два языка коэффициентов.** Внутри — типы Адепта; наружу в Гранд — идентификаторы. Пользователь видит оба.  
5. **Сверка.** Колонка «Excel» vs «движок» vs «после экспорта»; допуск 1 ₽. Ни Гранд, ни Адепт этого для чужого Excel не делают.  
6. **Печать не равна работе.** Переключатель вида; не 40 чекбоксов шаблона на первом экране (у Адепт стр. 902–904 — сила для профи, шум для конвертера).  
7. **Происхождение строки.** Метка источника: Excel лист 1.1 / Гранд XML / создано здесь. При конфликте импорта — не затирать молча.

Следующий шаг UI: каркас WebView2 с этой раскладкой на данных листа 1.1, без СНБ.
